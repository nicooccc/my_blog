## 1. 递归调用（P4–P7）

### 1.1 递归的例子：`nn_sum(n) = 1+2+…+n`

```c
int nn_sum(int n)
{
    int result;
    if (n <= 0)
        result = 0;
    else
        result = n + nn_sum(n - 1);
    return result;
}
```

对应的机器级代码（P4）：

```asm
nn_sum:
    pushl %ebp                # 保存旧 EBP
    movl  %esp, %ebp          # 建立当前帧底
    pushl %ebx                # 保存被调用者保存寄存器 EBX
    subl  $4, %esp            # 为"给下一层的实参"留 4 字节
    movl  8(%ebp), %ebx       # ebx = n
    movl  $0, %eax            # eax = 0（准备 result=0）
    cmpl  $0, %ebx            # 比较 n 与 0
    jle   .L2                 # n<=0 → 跳过递归，直接结束
    leal  -1(%ebx), %eax      # eax = n-1
    movl  %eax, (%esp)        # 实参 = n-1
    call  nn_sum              # 递归调用
    addl  %ebx, %eax          # eax = n + nn_sum(n-1)
.L2:
    addl  $4, %esp            # 释放实参区
    popl  %ebx                # 恢复 EBX
    popl  %ebp                # 恢复 EBP
    ret
```

**每层栈帧占 16 字节**：

| 栈帧内容 | 字节 |
|---|---|
| 实参区（`subl $4` 预留，存 n−1） | 4 |
| 返回地址 RA（`call` 压入） | 4 |
| 旧 EBP（`pushl %ebp`） | 4 |
| 旧 EBX（`pushl %ebx`） | 4 |
| **合计** | **16** |

> 注意：实参是"上一层帧底部"的区域，所以递归时每层都自带一块"给下一层的实参区"，这正是 16 字节里的第一部分。

### 1.2 递归时的栈帧链（P4 图）

```text
调用过程 P 的栈帧
  ┌────────────────────────────┐
  │ … （P 的其他内容）           │
  │ 实参 n                      │ ← P 给 nn_sum(n) 的参数
  ├────────────────────────────┤
  │ 返回地址 1                   │ ← P 调用 nn_sum 时 CALL 压入
  │ EBP 在 P 中的值              │ ← nn_sum(n) 的帧底（EBP）
  │ EBX 在 P 中的值              │
  │ 实参 n-1                    │ ← nn_sum(n) 给下一层准备的参数
  ├────────────────────────────┤
  │ 返回地址 2                   │
  │ EBP 在 nn_sum(n) 中的值      │ ← nn_sum(n-1) 的帧底
  │ EBX 在 nn_sum(n) 中的值      │
  │ 实参 n-2                    │
  ├────────────────────────────┤
  │ …（继续向下，直到 n<=0 不再递归）│
  └────────────────────────────┘
低地址
```

- 每进入一层递归，栈上就多一个 16 字节的帧，地址一路走低；
- 返回时从最内层开始，一层层 `ret` 弹回（`P → nn_sum(n) → nn_sum(n-1) → … → nn_sum(0)`，再反向返回）；
- 所以递归的函数调用深度 = 栈上同时存在的帧数。

### 1.3 递归的时空开销（P4、P6、P33）

| 维度 | 开销 |
|---|---|
| 时间 | 每次递归要执行准备/结束阶段的 16 条指令，共 **16n 条指令** |
| 空间 | 一次调用增加 16B 栈帧，共 **16n + 12 字节**（P 自己的帧至少 12B） |

> **为什么会栈溢出**：操作系统给进程分配的栈有默认上限（P5 实测 `ulimit -s` 为 **8192KB = 8MB**，不同系统可能不同）。递归深度太大，栈帧不断累积，超过上限就发生**栈溢出（stack overflow）**。

**课件结论**："为支持过程调用，每个过程都包含准备阶段和结束阶段。每增加一次过程调用，就要增加许多条额外指令，对程序性能影响很大，应尽量避免不必要的过程调用，特别是递归调用。"

### 1.4 单选题（P7）

> 以下有关递归过程调用的叙述中，错误的是（ ）

| 选项 | 判断 | 理由 |
|---|---|---|
| A 每次递归调用都会额外执行多条指令，因而时间开销大 | ✔ | 准备/结束阶段指令多 |
| B 每次递归调用都会生成一个新的栈帧，因而空间开销大 | ✔ | 每层 16B |
| C 每次递归调用在栈帧中保存的返回地址都不相同 | ✘ **相同** | 递归调用都发生在**同一个调用点**，返回地址就是 `call nn_sum` 的下一条指令地址，每层一模一样 |
| D 递归过程第一个参数的有效地址为 R[ebp]+8 | ✔ | 参数在 EBP+8 起 |

答案：**C**。

> 易错点：栈帧里**变化**的是实参（n、n-1、n-2…）、旧 EBP、旧 EBX；**不变**的是返回地址（同一调用点）。

## 2. 过程调用举例：数组越界会改掉栈帧里的什么？（P8–P11）

### 2.1 程序

```c
double fun(int i)
{
    volatile double d[1] = {3.14};
    volatile long int a[2];
    a[i] = 1073741824;          /* 可能越界：2^30 = 0x40000000 */
    return d[0];
}
```

运行结果：

```text
fun(0) → 3.14
fun(1) → 3.14
fun(2) → 3.1399998664856
fun(3) → 2.00000061035156
fun(4) → 3.14，然后存储保护错
```

> 应始终返回 `d[0]` 中的 3.14，但结果并非如此。Why？为什么不同 i 结果不同？为什么最终会保护错？

### 2.2 机器级代码（P10）

```asm
fun:
    pushl  %ebp
    movl   %esp, %ebp
    subl   $16, %esp            # 分配 16 字节栈帧
    fldl   .LC0                 # 把常数 3.14 压入浮点栈顶 ST(0)
    fstpl  -8(%ebp)             # d[0]（8 字节）存到 EBP-8 ~ EBP-1
    movl   8(%ebp), %eax        # eax = i
    movl   $1073741824, -16(%ebp,%eax,4)   # a[i] = 0x40000000
    fldl   -8(%ebp)             # 返回 d[0]
    leave
    ret

    .section .rodata
.LC0:
    .long  1374389535           # 3.14 的低 32 位 = 0x51EB851F
    .long  1074339512           # 3.14 的高 32 位 = 0x40091EB8
```

3.14 的 double 机器数就是 `0x40091EB851EB851F`（小端存放时低字在前）。

### 2.3 栈帧布局

```text
高地址
    ┌──────────────────────────────┐
    │ EBP+4  返回地址 RA            │  ← i=5 会写到这里
    ├──────────────────────────────┤
    │ EBP    保存的旧 EBP           │  ← i=4 会写到这里
    ├──────────────────────────────┤
    │ EBP-4  d[0] 高 4 字节 d7~d4   │  ← i=3 会写到这里
    │ EBP-8  d[0] 低 4 字节 d3~d0   │  ← i=2 会写到这里
    ├──────────────────────────────┤
    │ EBP-12 a[1]                  │  ← i=1 写入（合法）
    │ EBP-16 a[0]                  │  ← i=0 写入（合法）
    └──────────────────────────────┘
低地址
```

地址公式：`a[i]` 的地址 = `EBP-16 + 4*i`。i 每加 1，地址就**增加 4 字节**（往栈帧更高、更靠近 EBP 的一端挪），所以 i 越大，覆盖的单元越"危险"：先是 `d[0]`，再是保存的旧 EBP，最后是返回地址。

### 2.4 逐个 i 分析

| i | 写入地址 | 覆盖了谁 | 结果 |
|---|---|---|---|
| 0 | EBP-16 | `a[0]`（数组内） | 正常 3.14 |
| 1 | EBP-12 | `a[1]`（数组内） | 正常 3.14 |
| 2 | EBP-8 | `d[0]` 低 32 位（52 位尾数的最低 32 位） | 3.14 被改成一个略小的值：**3.1399998664856** |
| 3 | EBP-4 | `d[0]` 高 32 位（符号位 + 阶码 + 尾数高位） | 变成 **2.00000061035156** |
| 4 | EBP | 保存的旧 EBP | 返回 3.14 后，main 的 EBP 被破坏 → **存储保护错** |
| 5 | EBP+4 | 返回地址 | `ret` 跳到 `0x40000000` → **存储保护错/崩溃** |

**为什么 i=2、i=3 会得到这些数（逐位算）**

```text
原始 d[0] = 0x40091EB8 51EB851F    (3.14)

i=2：低 32 位被改成 0x40000000
     d[0] = 0x40091EB8 40000000 → 3.1399998664855957

i=3：高 32 位被改成 0x40000000
     d[0] = 0x40000000 51EB851F
     符号 s=0；阶码 0x400 → E=1；尾数 ≈ 1 + 0x51EB851F/2^52
     → 值 = (1 + 3.05e-7) × 2^1 ≈ 2.00000061035156
```

**为什么 i=4 是"先返回 3.14 再出错"**

- `i=4` 改的是**保存的旧 EBP**（内存里的那份），寄存器 EBP 本身没变；
- 所以 `fldl -8(%ebp)` 仍能读到 3.14，`ret` 也仍能从栈上取到正确的返回地址 → fun 正常返回 3.14；
- 但 `leave` 中的 `popl %ebp` 把**被污染的 0x40000000** 装进了 EBP；
- 回到 main 后，main 用 `%ebp` 访问局部变量、执行自己的 `leave` 时就会访问非法地址 → **存储保护错**。

> 若 `i=5`，直接覆盖返回地址，`ret` 一跳就崩，连 3.14 都返回不了。

### 2.5 从这里能学到什么

1. **数组越界不是"只改数组"**：栈帧里紧挨着数组的可能是其他局部变量、保存的寄存器、甚至返回地址；
2. 这就是**缓冲区溢出（buffer overflow）**攻击的机器级原理：精心构造越界数据可以改掉返回地址，让程序跳转到攻击者指定的代码；
3. **`volatile` 的作用**：告诉编译器"这个变量可能被意外修改"，禁止把它优化进寄存器、禁止跨语句复用，保证每次读写都真的访问内存——否则这个实验根本看不到效果；
4. **不同系统结果可能不同**：编译器对局部变量的分配方式（顺序、是否有填充）由实现决定，换个编译器/版本结果就变（P9 特别注明）。

## 3. 变量到底存在哪：存储映像与局部变量的分配（P12–P16）

### 3.1 IA-32/Linux 的存储映像（P5、P11 复习）

```text
高地址 0xFFFFFFFF
        ┌──────────────────────────────┐
        │ 内核虚存区（1GB）             │
0xC0000000 ├───────────────────────────┤
        │ 用户栈（动态生成，0xbfffxxxx）│ ← ESP，向低地址增长
        │ 共享库区域                    │
        │ 堆 heap（malloc，0x08xxxxxx） │ ← brk，向高地址增长
        │ 读写数据段 .data / .bss       │
        │ 只读代码段 .init/.text/.rodata│
0x08048000 ├───────────────────────────┤
        │ …                            │
0x00000000 └──────────────────────────────┘
低地址
```

- 只读代码段地址特点：**0x8048xxx**；
- 栈区地址特点：**0xbfffxxxx**（32 位 Linux）；
- 常量（如本例的 3.14）放在**只读数据区** `.rodata`（所以叫 `.LC0`）。

### 3.2 非静态局部变量的存储分配（P12）

| 结论 | 说明 |
|---|---|
| 分配在**本过程的栈帧**中 | `EBP-4`、`EBP-8` … |
| **顺序不保证** | C 标准没有规定必须按声明顺序分配，不同编译器处理方式不同 |
| 地址关系运算属**未定义行为** | 对不同变量的地址做除 `==`、`!=` 之外的关系运算（如 `&var1 < &var2`）都是 UB |
| 简单变量可能被放进寄存器 | 编译优化时，简单数据类型的变量分配在通用寄存器中 |
| 复杂类型**一定**在栈帧 | 数组、结构、联合等类型变量一定分配在栈帧中 |

### 3.3 实测：参数与局部变量的地址（P14）

```c
int func(int param1, int param2, int param3)
{
    int var1 = param1;
    int var2 = param2;
    int var3 = param3;
    printf("0x%p\n", &param1);   /* … */
}
int main() { func(1, 2, 3); return 0; }
```

课件实测输出（同一次运行）：

| 变量 | 地址 | 所在区 |
|---|---|---|
| param1 | 0x0020F930 | 栈（参数区） |
| param2 | 0x0020F92C | 栈（参数区） |
| param3 | 0x0020F928 | 栈（参数区） |
| var1 | 0x0020F924 | 栈（局部变量） |
| var2 | 0x0020F920 | 栈（局部变量） |
| var3 | 0x0020F934 | 栈（局部变量，**不连续**） |

**能读出三条结论**：

1. **参数地址总比局部变量地址大**——因为栈从高地址向低地址生长，参数先入栈，位于栈帧更高的一端；
2. **相邻参数地址相差 4**（32 位各占 4 字节）；
3. **局部变量不一定连续、也不一定按声明顺序**（var3 跳到了 0x0020F934）——正好印证 P12 的"分配顺序不保证"。

> 考点（按 IA-32 调用约定）：参数从**右往左**入栈，所以**最右边的参数地址最大**；局部变量地址比参数低。
> 注：截图里 param1 最大，是因为那次运行环境的参数传递方式不同（如 64 位下前几个参数走寄存器，再在栈帧里按声明顺序存放）；考试按 IA-32 栈传参的规则答即可。

### 3.4 实测：全局变量、静态变量与局部变量（P15）

```c
int g1 = 0, g2 = 0, g3 = 0;
int main()
{
    static int s1 = 0, s2 = 0, s3 = 0;
    int v1 = 0, v2 = 0, v3 = 0;
    /* 依次打印 &v1、&v2、&v3、&g1、&g2、&g3、&s1、&s2、&s3 */
}
```

| 变量 | 地址 | 存储区 |
|---|---|---|
| v1 / v2 / v3 | 0x0013FD28 / 0x0013FD24 / 0x0013FD20 | **栈区** |
| g1 / g2 / g3 | 0x00C43384 / 0x00C43380 / 0x00C4337C | **读写数据段** `.data` |
| s1 / s2 / s3 | 0x00C43374 / 0x00C43378 / 0x00C43388 | **读写数据段**（与全局变量同一区） |

**结论**：

- 全局变量和静态变量**连续存放在同一个存储区：可读写数据区**；
- 局部变量存放在**另一个存储区：栈区**；
- 所以同名不冲突（不同区），不同函数的局部变量同名也不冲突（不同栈帧）。

### 3.5 变量作用域与生存期（P12–P13）

| 变量种类 | 存储位置 | 生存期 | 初值 |
|---|---|---|---|
| 非静态局部（auto） | 栈帧 | 函数执行期间 | **不确定**（栈上残留值） |
| 静态局部（static） | 读写数据段 | 整个程序运行期间 | 未赋初值时 **0** |
| 全局 | 读写数据段（已初始化 `.data` / 未初始化 `.bss`） | 整个程序运行期间 | 未赋初值时 **0** |

**单选题（P13）**：以下叙述中错误的是（ ）

| 选项 | 判断 | 理由 |
|---|---|---|
| A 静态变量和非静态局部变量都分配在对应栈帧中 | ✘ | **static 在读写数据段**，不在栈帧 |
| B 非静态局部变量被分配在栈中，所以其作用域仅在过程体内 | ✔ | 局部变量只在本过程体内可见 |
| C 非静态局部变量可以和全局变量同名，是因为被分配在不同存储区 | ✔ | 栈区 vs 数据区 |
| D 不同过程中的非静态局部变量可以同名，是因为被分配在不同栈帧中 | ✔ | 各有各的栈帧 |

答案：**A**。

**单选题（P16）**：caller/add 程序中说法错误的是（ ）

| 选项 | 判断 | 理由 |
|---|---|---|
| A t1、t2、sum 被分配在寄存器或 caller 的栈帧中 | ✔ | 简单变量可进寄存器，否则在 caller 帧 |
| B 传参时 t2 和 t1 的值从高地址到低地址依次存入栈中 | ✔ | 从右往左入栈：t2 在高地址、t1 在低地址 |
| C 入口参数 t1 和 t2 的值被分配在 add 函数的栈帧中 | ✘ | **参数区在 caller 的栈帧里**，add 只是用 EBP+8/+12 去读 |
| D add 返回时返回值存放在 EAX 中 | ✔ | 32 位返回值在 EAX |

答案：**C**。

## 4. 三个"变量地址"经典例子（P17–P23）

### 4.1 例1：全局 x 与未初始化的局部 x

```c
int x = 100;
void main()
{
    int x;
    printf("x=%d\n", x);
}
```

输出不是 100，而是一个**随机数**（课件实测 `x=-1217400844`，再运行一次又变成 `x=-1217273868`）。

**原因**：C 语言中局部变量 `x` **屏蔽**了全局变量 `x`；局部变量分配在栈帧里，而**栈空间不会自动初始化**，它的值就是上一个函数留在那儿的"垃圾数据"。所以每次运行、每次调用栈的残留内容不同，打印结果就不同。

**机器级证据（P18）**：`main` 的反汇编

```asm
0804841c <main>:
 804841c: 55              push   %ebp
 804841d: 89 e5           mov    %esp,%ebp
 804841f: 83 e4 f0        and    $0xfffffff0,%esp
 8048422: 83 ec 20        sub    $0x20,%esp
 8048425: 8b 44 24 1c     mov    0x1c(%esp),%eax    # 直接取出"局部变量 x"（未赋值！）
 8048429: 89 44 24 04     mov    %eax,0x4(%esp)     # 作为 printf 的第 2 个实参
 804842d: c7 04 24 d0 84 04 08  movl $0x80484d0,(%esp)  # "x=%d\n" 的首地址
 8048434: e8 c7 fe ff ff  call   8048300 <printf@plt>
 8048439: c9              leave
 804843a: c3              ret
```

- 局部变量 `x` 的首地址是 `R[esp]+0x1c`；
- **没有任何一条指令给这块空间赋值**，却直接把它取出来当参数——所以打印的是栈上的残留值；
- 字符串 `"x=%d\n"` 在只读数据段（`0x80484d0`），常数不会被改。

**稍作修改后输出什么（P20）**

| 修改 | 输出 | 原因 |
|---|---|---|
| `int x=10;`（局部） | 10 | 局部变量已赋初值，屏蔽全局 |
| `static int x;`（局部静态） | 0 | static 放数据区，未赋初值时为 0 |

> 对比：**全局变量和 static 变量的初值一定是确定的**（程序给的初值，或未给时的 0）；**auto 局部变量不初始化就是不确定值**。

### 4.2 例2：`double *p = (double *)&a` 打印出 0.000000

网上的帖子（P21）：

```c
#include "stdafx.h"
int main(int argc, char* argv[])
{
    int a = 10;
    double *p = (double *)&a;
    printf("%f\n", *p);          // 结果 0.000000
    printf("%f\n", (double)a);   // 结果 10.000000
    return 0;
}
```

> 疑问：`*p` 和 `(double)a` 不都是"强制类型转换"吗？为什么结果不一样？

**看懂汇编就明白了（P22）**

```asm
int a = 10;
8048425: c7 44 24 28 0a 00 00 00   movl $0xa,0x28(%esp)

double *p = (double *)&a;
804842d: 8d 44 24 28               lea  0x28(%esp),%eax    # eax = &a
8048431: 89 44 24 2c               mov  %eax,0x2c(%esp)    # p = &a
     # 注意：指针的类型转换在汇编里没有任何指令，就是直接 mov

printf("%lf\n", *p);
8048435: 8b 44 24 2c               mov  0x2c(%esp),%eax   # eax = p
8048439: dd 00                     fldl (%eax)            # 按 double 加载 8 字节到 ST(0)
804843b: dd 5c 24 04               fstpl 0x4(%esp)        # 作为 printf 参数（64 位）
804843f: c7 04 24 00 85 04 08      movl $0x8048500,(%esp)
8048446: e8 b5 fe ff ff            call 8048300 <printf@plt>

printf("%lf\n", (double)a);
804844b: 8b 44 24 28               mov  0x28(%esp),%eax   # 取出 a
804844f: 89 44 24 1c               mov  %eax,0x1c(%esp)   # 未优化时的冗余搬运
8048453: db 44 24 1c               fildl 0x1c(%esp)       # 把 int 10 转换成 double 10.0
```

**关键差别：`fldl` 与 `fildl`**

| 写法 | 指令 | 含义 |
|---|---|---|
| `*p`（p 是 `double*`） | `fldl (%eax)` | 从 `&a` 开始**原封不动读 8 个字节**，按 double 格式解释 |
| `(double)a` | `fildl 0x1c(%esp)` | 先把 int 型的 10 **做数值转换**成 double 的 10.0 |

`a` 只占 4 个字节，`*p` 却读 8 个字节：低 4 字节是 `0x0000000A`，高 4 字节是 **`&a` 后面紧挨着的栈内容**（垃圾）。这 8 个字节按 double 解释时，**符号位和阶码全由那 4 个垃圾字节决定**。

- **Linux**：栈地址在 `0xbfffxxxx` 附近，高 4 字节形如 `0xbfff0028` → 符号位 s=1 → 负数（课件："打印出来的是一个负数"）；
- **Windows**：栈地址在 `0x0012FFxx` 附近，高 4 字节 `0x0012FFxx` → s=0、阶码≈0x001 → 极小正数 ≈ 1.001…×2^(-1022) → 打印 **0.000000**。

**结论（P23）**：帖子给出的结果是 **0.000000**，说明它是在 **Windows** 上运行得到的（Linux 上会打印一个负数）。两种系统**栈底地址不同**，ESP 内容不同，所以结果必然不同。

> 两个值得记住的点：
> ① 强制类型转换 `(double*)` **不产生任何指令**，只是让编译器"换个眼光看待这段内存"；
> ② 真正决定数值的指令是 `fldl`（重新解释位模式）还是 `fildl`（做数值转换）——这正是"同一串 0/1，按不同类型解释得到不同值"的最好例证。

## 5. 选择结构的机器级表示（P24–P31）

### 5.1 if-else 的两种翻译模板（P25）

任何 `if-else` 都翻译成"**一条条件转移 + 一条无条件转移**"，有两种等价写法：

**模板一：条件取反，跳到 else**

```text
        c = cond_expr;
        if (!c)
            goto false_label;
        then_statement
        goto done;
false_label:
        else_statement
done:
```

**模板二：条件不取反，跳到 then**

```text
        c = cond_expr;
        if (c)
            goto true_label;
        else_statement
        goto done;
true_label:
        then_statement
done:
```

- `Jcc` 负责"按条件选分支"；
- `JMP` 负责"执行完一个分支后跳过另一个分支"。

> 模板二的 then 代码在 else 之后，说明**"then 一定在 else 前面"是错的**（后面单选题的考点）。

### 5.2 例子：`get_cont`（P26）

```c
int get_cont(int *p1, int *p2)
{
    if (p1 > p2)
        return *p2;
    else
        return *p1;
}
```

```asm
    movl 8(%ebp),  %eax      # R[eax] ← M[R[ebp]+8]，即 p1
    movl 12(%ebp), %edx      # R[edx] ← M[R[ebp]+12]，即 p2
    cmpl %edx, %eax          # 比较 p1 和 p2（按 p1-p2 置标志）
    jbe  .L1                 # 若 p1<=p2，转 L1 执行
    movl (%edx), %eax        # R[eax] ← M[R[edx]]，即 M[p2]
    jmp  .L2                 # 无条件跳到 L2
.L1:
    movl (%eax), %eax        # R[eax] ← M[R[eax]]，即 M[p1]
.L2:
    # 结果在 EAX 中，作为返回值
```

**为什么用 `jbe`（无符号比较）而不是 `jle`（带符号）？**

- `p1`、`p2` 是**地址（指针）**，地址比较在 C 中按**无符号**进行；
- 所以编译器用 `jbe`（CF=1 或 ZF=1，无符号 A≤B），而不是 `jle`（SF≠OF 或 ZF=1，带符号）。
- 呼应上节课：**有符号比较用 G/L，无符号（含指针）比较用 A/B**。

参数位置：`p1` 在 `R[ebp]+8`、`p2` 在 `R[ebp]+12`；结果放 `EAX`。

### 5.3 单选题（P27）

> 关于 if-else 的机器级代码，错误的是（ ）

| 选项 | 判断 | 理由 |
|---|---|---|
| A 一定包含一条无条件转移指令 | ✔ | 需要一个 JMP 跳过另一分支 |
| B 一定包含一条条件转移指令 | ✔ | `Jcc` |
| C 计算 cond_expr 的代码一定在条件转移指令之前 | ✔ | 先算条件才能转移 |
| D then_statement 的代码一定在 else_statement 之前 | ✘ | 模板二就是 else 在前、then 在后 |

答案：**D**。

### 5.4 switch-case 的机器级表示（P28–P30）

**为什么需要跳转表**：连续写 `if-else-if` 时，每进一个 case 都要比较多次。若 case 的取值是**一段连续的小范围整数**，编译器就建一张**跳转表**，一次间接跳转直达目标，效率高得多。

**例子（P29）**

```c
int sw_test(int a, int b, int c)
{
    int result;
    switch (a) {
    case 15:
        c = b & 0x0f;          /* 没有 break，会继续执行 case 10 的代码 */
    case 10:
        result = c + 50;
        break;
    case 12:
    case 17:
        result = b + 50;
        break;
    case 14:
        result = b;
        break;
    default:
        result = a;
    }
    return result;
}
```

```asm
    movl 8(%ebp), %eax        # eax = a
    subl $10, %eax            # eax = a-10（把 10~17 映射成 0~7）
    cmpl $7, %eax
    ja   .L5                  # 无符号 >7 → 越界，转 default
    jmp  *.L8(,%eax,4)        # 间接转移：目标 = .L8 + 4*(a-10)

.L1:                          # a=15
    movl 12(%ebp), %eax
    andl $15, %eax            # eax = b & 0x0f
    movl %eax, 16(%ebp)       # c = b & 0x0f
.L2:                          # a=10
    movl 16(%ebp), %eax
    addl $50, %eax            # result = c + 50
    jmp  .L7
.L3:                          # a=12 或 17
    movl 12(%ebp), %eax
    addl $50, %eax            # result = b + 50
    jmp  .L7
.L4:                          # a=14
    movl 12(%ebp), %eax       # result = b
    jmp  .L7
.L5:                          # default
    addl $10, %eax            # eax 此时是 a-10，加回 10 得 a
.L7:
```

跳转表（放在 `.rodata` 只读节，4 字节边界对齐）：

```asm
    .section .rodata
    .align 4
.L8:
    .long .L2        # a=10 → result=c+50
    .long .L5        # a=11 → default
    .long .L3        # a=12 → result=b+50
    .long .L5        # a=13 → default
    .long .L4        # a=14 → result=b
    .long .L1        # a=15 → c=b&0x0f，然后落到 case 10
    .long .L5        # a=16 → default
    .long .L3        # a=17 → result=b+50
```

**要点解读**

- `a-10` 把 case 取值区间映射到 `0~7`，然后 `ja .L5` 做**一次**越界检查就处理了所有 `default` 情况；
- `jmp *.L8(,%eax,4)` 是**间接转移**：从表中取出第 `a-10` 项跳过去，**没有任何逐 case 的条件比较**；
- **fall-through**（case 15 没有 `break`）体现为 `.L1` 执行完直接顺序落入 `.L2`；
- 表在**只读节**，按 4 字节边界对齐（`align 4`）。

### 5.5 switch 小结（P30）

1. switch-case 和 if-else 嵌套可以实现同样功能；
2. 每个 case 对应的一段代码结束后，**都会有一条无条件转移指令**（`break` 对应的 `jmp`）；
3. 当 case 的**条件取值范围较小**时，可以用**跳转表**实现，此时 **case 中没有条件跳转指令**，执行效率高；
4. 编程中要根据具体情况权衡性能、成本、功耗（工程思维）。

**单选题（P31）**：错误的是（ ）

| 选项 | 判断 | 理由 |
|---|---|---|
| A 当 case 取值范围较小时可以用跳转表实现 | ✔ | |
| B 每个 case 至少对应一条条件转移指令，因而一定包含多条条件转移指令 | ✘ | 跳转表版本里 case 之间**没有**条件跳转 |
| C 每个 case 对应的代码结束后都会有一条无条件转移指令 | ✔ | `break` → `jmp` |
| D 可以用连续的 if-else-if 实现 switch | ✔ | 语义等价，只是效率低 |

答案：**B**。

## 6. 循环结构的机器级表示（P32–P38）

### 6.1 三种循环的翻译模板（P34）

**do-while**

```text
loop:
      loop_body_statement
      c = cond_expr;
      if (c) goto loop;
```

**while**

```text
      c = cond_expr;
      if (!c) goto done;
loop:
      loop_body_statement
      c = cond_expr;
      if (c) goto loop;
done:
```

**for**

```text
      begin_expr;
      c = cond_expr;
      if (!c) goto done;
loop:
      loop_body_statement
      update_expr;
      c = cond_expr;
      if (c) goto loop;
done:
```

> 共同点：**循环体 + 末尾的条件转移**（`if (c) goto loop`）是核心；while/for 在进入循环前多一次"首次判断"，以便循环次数为 0 时能直接跳过。

### 6.2 例子：用循环实现 `nn_sum`（P35）

```c
int nn_sum(int n)
{
    int i;
    int result = 0;
    for (i = 1; i <= n; i++)
        result += i;
    return result;
}
```

```asm
    movl 8(%ebp), %ecx        # ecx = n
    movl $0, %eax             # eax = result = 0
    movl $1, %edx             # edx = i = 1
    cmpl %ecx, %edx           # 首次判断：i 与 n 比较
    jg   .L2                  # 若 i>n（带符号），直接跳出
.L1:
    addl %edx, %eax           # result += i
    addl $1, %edx             # i++
    cmpl %ecx, %edx           # 更新后再次比较
    jle  .L1                  # 若 i<=n，继续循环
.L2:
```

**观察**：

- 局部变量 `i`、`result` 被分配到 **EDX、EAX 寄存器**里（简单变量，编译器优化）；
- 循环结束判断用 `cmpl` + **带符号** `jg/jle`（因为 `i`、`n` 是 int）；
- 整个过程**没有任何函数调用**，也不产生新栈帧；如果过程体没有用到被调用者保存寄存器，栈帧里只需保存 EBP（**4 字节**）。

### 6.3 递归 vs 循环：开销对比（P33、P35）

| 维度 | 递归版 `nn_sum` | 循环版 `nn_sum` |
|---|---|---|
| 时间 | 每次调用约 16 条指令，共 **16n 条** | 每轮 4 条指令（addl / addl / cmpl / jle），共约 **4n 条** |
| 空间 | **16n + 12 字节** 栈帧 | 仅 **4 字节**（保存 EBP） |
| 额外开销 | 每层都要准备参数、保存现场、建帧、退帧 | 无函数调用 |
| 可读性 | 与数学定义一致，简洁 | 需要显式循环变量 |

课件结论：递归方式比循环方式**多用了 (16n+8) 字节栈空间**，并且**至少多执行 16n 条指令**。所以"若能用非递归方式实现，最好用非递归方式"。

### 6.4 循环小结（P36）

1. 循环结构**至少包含一条条件转移指令**；
2. 循环结束条件通常用一条**比较指令 CMP** 来实现，再用 Jcc 判断；
3. 循环执行效率比递归高；
4. 编程中尽量用循环代替递归，提高程序性能。

**单选题（P37）**：错误的是（ ）

| 选项 | 判断 | 理由 |
|---|---|---|
| A 一定至少包含一条条件转移指令 | ✔ | 循环靠 Jcc 回跳/跳出 |
| B 不一定包含无条件转移指令 | ✔ | do-while 只靠 Jcc 就能实现（无 JMP） |
| C 循环结束条件通常用一条比较指令 CMP 来实现 | ✔ | `cmpl` + `jcc` |
| D 循环体内执行的指令不包含条件转移指令 | ✘ | 循环体内完全可以是 if 语句（甚至循环嵌套），当然含条件转移 |

答案：**D**。

### 7.2 高频考点与易错点

| 易错点 | 正确认识 |
|---|---|
| 递归时每层返回地址不同 | 同一调用点 → **返回地址相同**，变化的是实参、旧 EBP、旧 EBX |
| 递归只费空间不费时间 | 每层还有准备/结束指令，**时间也是 O(n) 且常数大** |
| 数组越界只影响数组 | 栈帧里紧挨着的是其他局部变量、旧 EBP、**返回地址** |
| auto 局部变量不初始化是 0 | 是**随机值**（栈上残留）；static/全局才是 0 |
| static 变量在栈上 | static 在**读写数据段**，全程有效 |
| 局部变量按声明顺序分配 | C 标准未规定；对地址做 `<`、`>` 比较是 **UB** |
| 参数的地址比局部变量小 | 参数在栈帧更高的一端（**参数地址 > 局部变量地址**） |
| IA-32 参数从左往右入栈 | **从右往左**，最右边参数地址最大 |
| 指针转换会生成指令 | `(double*)` 等指针类型转换**不生成任何指令** |
| `(double)a` 与 `*(double*)&a` 等价 | 前者是**数值转换**（`fildl`），后者是**位模式重解释**（`fldl`） |
| if-else 里 then 总在 else 前面 | 编译器可交换两分支顺序（模板二） |
| switch 每个 case 都有条件跳转 | 跳转表实现时**没有**逐 case 的条件跳转 |
| 循环一定有无条件转移 | do-while 可以只有 Jcc |
| 循环体里不会有条件转移 | 循环体内可以有 if/嵌套循环，自然含 Jcc |
