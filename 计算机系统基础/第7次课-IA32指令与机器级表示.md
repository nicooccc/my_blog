## 0. 课前回顾：3.3（上）的知识底座

### 0.1 从 C 到机器码：GCC 的四个阶段（P1）

| 阶段 | 工具 | 输入 → 输出 | 说明 |
|---|---|---|---|
| 预处理 | cpp | `.c` → `.i` | 插入 `#include` 的文件、展开 `#define` 宏 |
| 编译 | cc1 | `.i` → `.s` | 生成汇编语言程序 |
| 汇编 | as | `.s` → `.o` | 生成**可重定位**的机器语言目标文件 |
| 链接 | ld | 多个 `.o` + 库 → 可执行文件 | 如 `printf` 等库例程在此拼接进来 |

> **要点**：汇编指令与机器指令基本一一对应；一条高级语言语句通常对应**多条**机器指令；同一个 C 程序经不同优化选项可得到不同的机器级程序。

### 0.2 三种指令操作数（P2）

| 类型 | 书写形式 | 含义 | 特点 |
|---|---|---|---|
| 立即数 | `$0x1` | 操作数直接编码在指令中 | 取出指令即得，最快 |
| 寄存器操作数 | `%eax` | 指令给出寄存器编号 | 分为定点寄存器组、浮点寄存器栈、多媒体扩展寄存器组 |
| 存储器操作数 | `(%eax)` | 指令给出（有效）地址 | 需按段页式寻址计算地址，第6章展开 |

### 0.3 定点寄存器组：8 通用 + 2 专用 + 6 段（P3）

| 32位 | 16位 | 8位（高/低） | 用途 |
|---|---|---|---|
| EAX | AX | AH / AL | 累加器（乘法/除法/返回值的默认位置） |
| EBX | BX | BH / BL | 基址寄存器（被调用者保存） |
| ECX | CX | CH / CL | 计数寄存器（循环、移位次数） |
| EDX | DX | DH / DL | 数据寄存器（乘除高位、64位返回值） |
| ESP | SP | — | 栈指针（指向栈顶） |
| EBP | BP | — | 基址/帧指针（指向当前栈帧底部） |
| ESI | SI | — | 源变址寄存器 |
| EDI | DI | — | 目的变址寄存器 |
| EIP | IP | — | 指令指针（PC） |
| EFLAGS | FLAGS | — | 标志寄存器 |

段寄存器 6 个：CS（代码段）、SS（堆栈段）、DS（数据段）、ES/FS/GS（附加段）。

> **要点**：带 E 的是 32 位，去掉 E 是低 16 位；AX/BX/CX/DX 还可再拆成高低两个 8 位（AH/AL 等）。所以 EAX 是"套娃"：EAX ⊃ AX ⊃ AH/AL。

### 0.4 常用标志（P4、P9）

| 标志 | 名称 | 置位条件 |
|---|---|---|
| SF | 符号标志 | 结果最高位（带符号数的符号） |
| ZF | 零标志 | 结果为 0 时 ZF=1，否则 ZF=0 |
| OF | 溢出标志 | **带符号**运算结果超出表示范围时 OF=1 |
| CF | 进位/借位标志 | **无符号**加减运算的进位/借位，`CF = Sub ⊕ Co` |

> **易错**：OF 与 CF 不是一回事，前者管"带符号溢出"，后者管"无符号进位/借位"，后面控制转移全靠它俩区分有/无符号比较。

### 0.5 保护模式寻址方式（P5）

| 寻址方式 | 线性地址 LA |
|---|---|
| 立即寻址 | 指令直接给出操作数 |
| 寄存器寻址 | 操作数 = 指定寄存器 R 的内容 |
| 位移 | LA = (SR) + A |
| 基址寻址 | LA = (SR) + (B) |
| 基址加位移 | LA = (SR) + (B) + A |
| 比例变址加位移 | LA = (SR) + (I)×S + A |
| 基址加变址加位移 | LA = (SR) + (B) + (I) + A |
| 基址加比例变址加位移 | LA = (SR) + (B) + (I)×S + A |
| 相对寻址 | LA = (PC) + A |

其中：A=位移量，B=基址寄存器，I=变址寄存器，S=比例系数（1/2/4/8），SR=段寄存器，(X) 表示 X 的内容。

典型写法：`movw 504(%ebp,%esi,2), %ax` 表示 `M[(SR)+(ebp)+(esi)*2+504]`。

### 0.6 传送类指令速查（P6–P8）

| 指令 | 功能 | 说明 |
|---|---|---|
| MOV | 一般传送 | `movb/movw/movl` 分别 8/16/32 位；可截断（高位到低位） |
| MOVS | 符号扩展传送 | 短源数据高位补符号位，适用于**带符号**整型，如 `movsbw` |
| MOVZ | 零扩展传送 | 短源数据高位补 0，适用于**无符号**整型，如 `movzwl` |
| XCHG | 交换 | 两个寄存器内容互换，`xchgb` 为字节交换 |
| PUSH | 压栈 | 先 `R[sp]←R[sp]-2/-4`，再把字/双字写入 SP/ESP 指示单元 |
| POP | 出栈 | 先取出栈顶字/双字，再 `R[sp]←R[sp]+2/+4` |
| LEA | 加载有效地址 | 把源操作数的**地址**（不是内容）送入目的寄存器 |

> **栈为什么"低字节在栈顶"**：IA-32 采用**小端**方式，`push` 一次写 4 字节时低地址存低字节，所以 AL 在栈顶。栈从高地址向低地址增长，且"栈"不等于"堆栈"。

**LEA 的两个常用例子**（P8）：

```asm
leal (%edx,%eax), %eax        # R[eax] ← R[edx] + R[eax]      （执行后 eax = i+j）
leal 8(%edx,%eax,2), %eax     # R[eax] ← R[edx] + 2*R[eax] + 8
```

`lea` 本质上是在"算地址"，所以常被编译器拿来当**不影响标志的加法**用（见 4.7 中 `leal (%edx,%eax),%eax` 实现 x+y）。

### 0.7 定点算术运算指令速查（P9、P10）

| 类别 | 指令 | 说明 |
|---|---|---|
| 加/减 | ADD/SUB（b/w/l） | 影响 OF/CF/SF/ZF，不区分有无符号 |
| 增1/减1 | INC/DEC | 影响除 CF 外的标志 |
| 取负 | NEG | 各位取反末位加1；对 0 取负结果为 0 且 CF=0，否则 CF=1 |
| 比较 | CMP | 做减法得标志，结果**不写回**目的操作数 |
| 乘 | MUL/IMUL | 无符号乘/带符号乘，影响 OF 和 CF |
| 除 | DIV/IDIV | 无符号除/带符号除 |

**乘法/除法的隐含操作数**（考试常考）：

| 位宽 | 乘法（被乘数 × 源操作数） | 结果存放 |
|---|---|---|
| 8 位 | AL × SRC8 | AX（AH:AL） |
| 16 位 | AX × SRC16 | DX:AX |
| 32 位 | EAX × SRC32 | EDX:EAX |

| 位宽 | 除法（被除数 ÷ 源操作数） | 商 / 余数 |
|---|---|---|
| 8 位 | AX ÷ SRC8 | AL / AH |
| 16 位 | DX:AX ÷ SRC16 | AX / DX |
| 32 位 | EDX:EAX ÷ SRC32 | EAX / EDX |

补充：IMUL 可给出 1/2/3 个操作数（2/3 操作数时结果截断为 n 位）；MUL 只能给 1 个操作数。对 mul，若乘积高 n 位全 0 则 OF=CF=0；对 imul，若乘积高 n+1 位全 0 或全 1 则 OF=CF=0。

## 1. 按位运算指令（P13–P16）

### 1.1 逻辑运算：NOT / AND / OR / XOR / TEST

| 指令 | 功能 | 对标志的影响 |
|---|---|---|
| NOT | 按位取反 | **不影响标志** |
| AND | 按位与 | OF=CF=0，ZF/SF 按结果设置 |
| OR | 按位或 | OF=CF=0，ZF/SF 按结果设置 |
| XOR | 按位异或 | OF=CF=0，ZF/SF 按结果设置 |
| TEST | 做"与"但不写回 | 与 AND 相同（只影响标志） |

全 0 时 ZF=1；最高位为 1 时 SF=1。

**常见用途**：

```asm
andl $0xFFFFFF7F, %eax   # 清第 7 位（掩码：要清零的位给 0）
orl  $0x00000080, %eax   # 置第 7 位（掩码：要置 1 的位给 1）
xorl $0x000000FF, %eax   # 翻转低 8 位
testl $0x00000080, %eax  # 只看第 7 位，不修改 eax
xorl %eax, %eax          # 最快的清零方式（同时 ZF=1）  
```

> **考点**：`XOR 1⊕1=0，0⊕0=0，0⊕1=1，1⊕0=1`；`AND` 乘性（有 0 则 0）；`OR` 加性（有 1 则 1）。寄存器自身异或是清零的经典技巧。

### 1.2 移位与循环移位

| 指令 | 名称 | 移位规则 | CF |
|---|---|---|---|
| SHL | 逻辑左移 | 低位补 0 | 最后移出的位 |
| SHR | 逻辑右移 | 高位补 0 | 最后移出的位 |
| SAL | 算术左移 | 低位补 0（与 SHL 相同） | 最后移出的位 |
| SAR | 算术右移 | 高位补**符号位** | 最后移出的位 |
| ROL/ROR | 循环左/右移 | 移出的位补到另一端，不带 CF | 最后移出的位 |
| RCL/RCR | 带进位循环 | CF 作为"环"的一部分参与移位 | 最后移出的位 |

书写形式：`shll $2, %eax`（立即数给出次数）或 `shrl %cl, %eax`（次数大于 1 时用 CL）。左移时若移位前后符号位不同，则 OF=1（溢出）。

> **记忆**：`S=Shift`、`A=Arithmetic`（算术，照顾符号）、`L/R=左/右`；`R=Rotate`（循环）、`C=Carry`（把 CF 卷入循环）。

### 1.3 例3.6：移位 + 加法的组合（P14）

> 设 short 型变量 x 分配在 AX 中，`R[ax]=FF80H`，执行下列代码后 x 的机器数和真值？

```asm
movw %ax, %dx     # dx = FF80
salw $2, %ax      # ax = FF80 << 2 = FE00
addw %dx, %ax     # ax = FE00 + FF80 = 1FD80 → 截断为 FD80
sarw $1, %ax      # ax = FD80 >> 1（算术右移）= FEC0
```

逐位验证：

```text
FF80 = 1111 1111 1000 0000   （x = -128）
<<2  = 1111 1110 0000 0000   （FE00，符号位仍为 1 → OF=0）
+FF80= 1111 1101 1000 0000   （FD80，最高位进位 1 被丢弃，CF=1）
>>1  = 1111 1110 1100 0000   （FEC0，算术右移高位补 1）
```

结果：机器数 **FEC0H**，真值 **-320**。

验证：原式等价于 `((x<<2) + x) >> 1 = 5x/2`；x=-128 时 5×(-128)/2 = -320，正确。

> **逆向工程**：由汇编指令序列反推高级语言表达式（这里是 `5*x/2`），是本章的重要能力。

### 1.4 移位举例：`int` 与 `unsigned` 右移的区别（P15）

```c
#include <stdio.h>
void main()
{
    int a = 0x80000000;          /* -2147483648，带符号 */
    unsigned int b = 0x80000000; /*  2147483648，无符号 */
    printf("a= 0x%X\n", a >> 1);
    printf("b= 0x%X\n", b >> 1);
}
```

对应汇编（截取关键部分）：

```asm
movl 0x80000000, 0x1c(%esp)   # a
movl 0x80000000, 0x18(%esp)   # b
mov  0x1c(%esp), %eax
sar  %eax                     # a >> 1 用算术右移 → C0000000
...
mov  0x18(%esp), %eax
shr  %eax                     # b >> 1 用逻辑右移 → 40000000
```

输出：`a= 0xC0000000`（= -1073741824），`b= 0x40000000`（= 1073741824）。

> **结论**：编译器根据操作数的**类型**选择 `sar` 还是 `shr`。同样是 `>>1`，有符号数补符号位，无符号数补 0。

### 1.5 单选题：`salw $2, %ax`（P16）

> 设 short 型变量 x 在 AX 中，`R[ax]=FF70H`，执行 `salw $2, %ax` 后 x 的机器数和真值？

```text
FF70 = 1111 1111 0111 0000   （x = -144）
<<2  = 1111 1101 1100 0000   （FDC0，符号位前后都是 1 → OF=0）
```

答案：**A. FDC0H，-576**（-144×4 = -576）。

干扰项分析：`FFDCH` 是右移两位的结果；`FDC3H` 是左移时低位补错；`3FDCH` 是没处理符号位。**做移位题一定先判断是逻辑移位还是算术移位。**

## 2. 控制转移指令（P17–P33）

### 2.1 总览（P18）

| 指令 | 作用 |
|---|---|
| JMP DST | 无条件转移到 DST |
| Jcc DST | 条件转移：cc 为条件码，满足则转 DST，否则顺序执行 |
| SETcc DST | 条件设置：把条件码 cc 对应的 0/1 存入 DST（通常是 8 位寄存器） |
| CMOVcc DST, SRC | 条件传送：满足条件才传送，否则什么都不做 |
| CALL DST | 调用：返回地址 RA 入栈，转 DST 执行 |
| RET | 返回：从栈中弹出 RA，转到 RA 处执行 |
| INT / IRET | 中断/中断返回（第7、8章） |

### 2.2 标志为什么能"比较大小"：减法统一由加法器完成（P20）

比较 X 和 Y，机器实际做的是 **X − Y**，然后看标志。减法之所以能做，是因为补码把减法变成了加法：

```text
X − Y = X + (~Y) + 1
```

加/减运算部件（P26）的输入是 A（目的操作数）和 B（源操作数），`Sub` 控制 B 是否取反加 1：

- `Sub=0`：做 A+B
- `Sub=1`：做 A−B
- 输出：Result、ZF、SF、OF、`CF = Co ⊕ Sub`（Co 为加法器最高位进位）

**4 位例子**（P20）：

```text
X = 1001   （无符号 9，带符号 -7）
Y = 1100   （无符号 12，带符号 -4）

X − Y：1001 + (1100 取反+1) = 1001 + 0100 = 1101，Co = 0
       CF = 1 ⊕ 0 = 1  → 无符号借位，X < Y
       SF = 1（最高位为1），ZF = 0
       OF = 0（-7 - (-4) = -3，未溢出）
结论：无符号 CF=1 AND ZF=0 → X<Y；带符号 OF≠SF AND ZF=0 → X<Y
```

```text
X = 1100，Y = 1001
X − Y：1100 + 0111 = 1 0011，Co = 1
       CF = 1 ⊕ 1 = 0 → 无符号无借位，X > Y
       结果 0011 → SF=0，ZF=0；OF=0（-4 - (-7) = 3）
结论：无符号 CF=0 AND ZF=0 → X>Y；带符号 OF=SF AND ZF=0 → X>Y
```

由此得到比较判据（**考试必背**）：

| 比较 | 无符号数 | 带符号数 |
|---|---|---|
| X < Y | CF=1 AND ZF=0 | SF≠OF AND ZF=0 |
| X ≤ Y | CF=1 OR ZF=1 | SF≠OF OR ZF=1 |
| X > Y | CF=0 AND ZF=0 | SF=OF AND ZF=0 |
| X ≥ Y | CF=0 OR ZF=1 | SF=OF OR ZF=1 |

> **为什么带符号看 OF 和 SF**：结果符号位 SF 可能因为溢出"翻转"，把 SF 和 OF 异或一下才是真实的符号关系。无符号没有"溢出"概念（进位就是 CF），所以只看 CF 和 ZF。

### 2.3 条件转移指令完整表（P19、P28）

| 序号 | 指令 | 转移条件 | 说明 |
|---|---|---|---|
| 1 | JC label | CF=1 | 有进位/借位 |
| 2 | JNC label | CF=0 | 无进位/借位 |
| 3 | JE/JZ label | ZF=1 | 相等/等于零 |
| 4 | JNE/JNZ label | ZF=0 | 不相等/不等于零 |
| 5 | JS label | SF=1 | 是负数 |
| 6 | JNS label | SF=0 | 是非负数 |
| 7 | JO label | OF=1 | 有溢出 |
| 8 | JNO label | OF=0 | 无溢出 |
| 9 | JA/JNBE label | CF=0 AND ZF=0 | 无符号整数 A>B |
| 10 | JAE/JNB label | CF=0 OR ZF=1 | 无符号整数 A≥B |
| 11 | JB/JNAE label | CF=1 AND ZF=0 | 无符号整数 A<B |
| 12 | JBE/JNA label | CF=1 OR ZF=1 | 无符号整数 A≤B |
| 13 | JG/JNLE label | SF=OF AND ZF=0 | 带符号整数 A>B |
| 14 | JGE/JNL label | SF=OF OR ZF=1 | 带符号整数 A≥B |
| 15 | JL/JNGE label | SF≠OF AND ZF=0 | 带符号整数 A<B |
| 16 | JLE/JNG label | SF≠OF OR ZF=1 | 带符号整数 A≤B |

**记忆方法**：分三类——只看单个标志的（JC/JNC/JE/JNE/JS/JNS/JO/JNO）；无符号比较用 **A/B**（Above/Below）加 E；带符号比较用 **G/L**（Greater/Less）加 E。别名（JNBE=JA 等）只是"换个说法"，条件不变。

### 2.4 条件设置与条件传送（P21–P24）

**SETcc**：把条件码变成 0/1 写进 8 位寄存器。

```asm
setc  %dl      # 若 CF=1，则 R[dl]=1；否则 R[dl]=0
setge %dl      # 若 SF=OF 或 ZF=1，则 R[dl]=1；否则 R[dl]=0
```

每个 Jcc 都有对应的 SETcc，条件完全一致。SETcc 常用来实现 C 的关系表达式结果（`i<j`、`a==b` 等）。

**CMOVcc**：条件满足才传送，否则"什么都不做"。相比 Jcc 可以避免分支预测失败，是现代编译器常用的优化手段。

```asm
cmovc  %eax, %edx        # CF=1 则 R[edx]=R[eax]
cmovge (%eax), %edx      # SF=OF 或 ZF=1 则 R[edx]=M[R[eax]]
```

**例子：C 表达式类型转换顺序**（P22–P23）

转换等级（低的向高的转）：

```text
unsigned long long
        ↑
    long long
        ↑
   unsigned int
        ↑
       int
        ↑
 (unsigned) char, short
```

> 规则：char/short 先做整型提升为 int；两边等级不同则低等级转高等级；若同等级中有 unsigned，则转成 unsigned。

```c
#include <stdio.h>
void main()
{
    unsigned int a = 1;
    unsigned short b = 1;
    char c = -1;
    int d;

    d = (a > c) ? 1 : 0;   printf("%d\n", d);
    d = (b > c) ? 1 : 0;   printf("%d\n", d);
}
```

运行结果：

```text
0
1
```

汇编（关键片段）：

```asm
movw  $0x1, 0x1a(%esp)        # b = 1
movb  $0xff, 0x19(%esp)       # c = -1
movsbl 0x19(%esp), %eax       # 取出 c 并符号扩展 → FFFFFFFF
cmpl  0x1c(%esp), %eax        # 无符号比较：c 与 a
setb  %al                     # c < a（无符号 below）→ 等价于 a > c，结果 0

movzwl 0x1a(%esp), %edx       # b 零扩展 → 1
movsbl 0x19(%esp), %eax       # c 符号扩展 → -1
cmp   %eax, %edx              # 带符号比较：1 与 -1
setg  %al                     # 1 > -1（带符号 greater）→ 结果 1
```

> **解析**：
> ① `a` 是 unsigned int，`c=-1` 被转成 unsigned int 后是 4294967295，`1 > 4294967295` 为假 → 0；
> ② `b` 提升为 int（值为 1），`c` 提升为 int（值为 -1），`1 > -1` 为真 → 1。
> ③ 同一串比特 `FFFFFFFF`，按无符号解释是 4294967295，带符号解释是 -1，**用错条件码结果就完全相反**。这就是编译器对前者用 `setb`（无符号）、后者用 `setg`（带符号）的原因。

### 2.5 经典案例：`sum(int a[], unsigned len)` 为什么会越界（P25–P30）

```c
int sum(int a[], unsigned len)
{
    int i, sum = 0;
    for (i = 0; i <= len - 1; i++)
        sum += a[i];
    return sum;
}
```

> 问题：当实参 `len=0` 时返回值应该是 0，但在机器上执行却发生了**存储器访问异常**。Why？

编译器生成的循环判断部分：

```asm
.L3:
    ...
    movl  -4(%ebp), %eax      # eax = i
    movl  12(%ebp), %edx      # edx = len
    subl  $1, %edx            # edx = len - 1
    cmpl  %edx, %eax          # 比较 i 与 len-1
    jbe   .L3                 # 无符号 <= 则继续循环
    ...
```

**第一步：`subl $1, %edx`（len=0）**

```text
A = edx = 0000 0000H（len），B = 0000 0001H（立即数 1），Sub = 1
Result = A - B = FFFF FFFFH（32 个 1）
CF = Co ⊕ Sub = 0 ⊕ 1 = 1（借位）
ZF=0，SF=1（最高位为1），OF=0
```

**第二步：`cmpl %edx, %eax`（i=0，len-1=FFFFFFFF）**

```text
A = eax = 0000 0000H（i），B = edx = FFFF FFFFH，Sub = 1
Result = 0000 0000 - FFFF FFFF = 0000 0001
CF = Co ⊕ Sub = 0 ⊕ 1 = 1，ZF = 0，OF = 0，SF = 0
```

**第三步：`jbe .L3`**：条件 `CF=1 OR ZF=1`，现在 CF=1 → **满足，继续循环**。

于是在 `i` 从 0 开始递增的过程中，不等式 `i <= 0xFFFFFFFF`（无符号）永远成立，循环不断执行，`a[i]` 越界，最终触发存储器访问异常。

> **根源**：C 语言里 `len` 是 unsigned，`len-1` 也是 unsigned；`i`（int）在与 `len-1` 比较时被隐式转换为 unsigned，于是编译器生成**无符号比较** `jbe`。`len=0` 时 `len-1` 发生下溢变成 0xFFFFFFFF，比较条件恒真。

**正确写法**：把 `len` 声明为 int。

```c
int sum(int a[], int len)
{
    int i, sum = 0;
    for (i = 0; i <= len - 1; i++)
        sum += a[i];
    return sum;
}
```

此时 `len-1 = -1`，汇编把 `jbe` 换成 `jle`（带符号比较）：

```asm
subl $1, %edx
cmpl %edx, %eax
jle  .L3        # 带符号 <=
```

标志仍是 CF=1、ZF=0、OF=0、SF=0，但 `jle` 的条件是 `SF≠OF OR ZF=1`：0≠0 为假且 ZF=0 → **不满足，退出循环**，返回 0，结果正确。

> **更稳妥的写法**：`for (i = 0; i < len; i++)`，从根本上避免 `len-1` 的下溢，也就不用担心 unsigned 的陷阱。

### 2.6 单选题：`if (i < j)` 的指令序列（P31）

> 程序 P 中有两个 int 变量 i 和 j，分别分配在 EAX 和 EDX 中，P 中存在 `if (i<j) {…};`，该 if 语句对应的指令序列**一定不会是**（ ）

| 选项 | 指令序列 | 能否正确实现 | 理由 |
|---|---|---|---|
| A | `cmpl %eax,%edx` `jle L` | 能 | 算 j−i；j≤i（即 i<j 不成立）时跳到 else |
| B | `cmpl %edx,%eax` `jl L` | 能 | 算 i−j；i<j 时跳到函数体 |
| C | `cmpl %eax,%edx` `ja L` | **不能** | `ja` 是**无符号**比较，i、j 是 int，出现负数时结论错误 |
| D | `cmpl %eax,%edx` `jg L` | 能 | 算 j−i；j>i（即 i<j）时跳到函数体 |

答案：**C**。

> **考点**：带符号 int 的比较只能用 `jl/jg/jle/jge`（看 SF/OF），不能用 `jb/ja/jbe/jae`（看 CF）。反过来，无符号数比较用 A/B 系列。

### 2.7 转移地址计算：相对寻址 + 小端（P33）

已知 IA-32 是小端，反汇编结果如下：

```asm
804838c: 74 08              je    xxxxxxxx
804838e: e8 1e 00 00 00     call  80483b1 <test>
```

**问题 1**：`je` 的目标地址？je 指令操作码是 01110100b。

```text
je 是 2 字节指令（1 字节操作码 + 1 字节 rel8），取指完成后 PC = 0x804838c + 2
转移目标 = PC + 符号扩展的偏移量 = 0x804838c + 2 + 0x08 = 0x8048396
```

**问题 2**：`call` 指令中的 0x80483b1 怎么反汇编出来？

```text
call 操作码 e8，后面 4 字节是按小端存放的偏移量：1e 00 00 00 → 0x0000001e
call 指令共 5 字节，取指完成后 PC = 0x804838e + 5
目标地址 = 0x804838e + 5 + 0x1e = 0x80483b1
```

> **结论**：转移类指令用的是**相对寻址**（LA = (PC) + A），偏移量是相对"下一条指令地址"的补码，可正可负，所以既能向前跳也能向后跳。常见长度：`je rel8` 2 字节，`jmp rel32` 5 字节，`call rel32` 5 字节。

### 2.8 调用和返回指令（P32）

| 指令 | 动作 |
|---|---|
| CALL DST | ① 返回地址（下条指令地址）入栈（相当于 PUSH）；② 转移到 DST 执行（跳转方式与 JMP 类似） |
| RET | 从栈顶取出返回地址（相当于 POP），送到 EIP 和 CS，继续执行 |

> CALL/RET 是"过程调用"的实现基础：CALL 负责"去了还能回来"，RET 负责"回来"。过程调用的完整步骤见第 4 节。

## 3. x87 浮点指令与 MMX/SSE 指令（P34–P49）

### 3.1 两种浮点处理架构（P35、P39）

| 架构 | 寄存器 | 特点 |
|---|---|---|
| x87 FPU（浮点协处理器） | 8 个 80 位寄存器 ST(0)–ST(7)，**栈结构**，ST(0) 为栈顶 | 80 位扩展精度；gcc 默认生成 x87 代码 |
| MMX | 8 个 64 位寄存器 MM0–MM7 | 借用 ST(0)–ST(7) 的低 64 位；可同时处理 8 字节/4 字/2 双字/1 个 64 位数据 |
| SSE | 8 个 128 位寄存器 XMM0–XMM7 | SIMD（单指令多数据）；可同时处理 16 字节/8 字/4 双字/2 四字；SSE2 起支持 128 位整数运算和 2 个双精度浮点数 |

> MMX 并没有带来 3D 游戏性能的显著提升，随后推出的 SSE 才真正用上了 SIMD（数据级并行）技术。IA-32 通用寄存器的编号表（P36）很能说明"体系结构兼容"：

| 编号 | 8 位 | 16 位 | 32 位 | 64 位 | 128 位 |
|---|---|---|---|---|---|
| 000 | AL | AX | EAX | MM0 / ST(0) | XMM0 |
| 001 | CL | CX | ECX | MM1 / ST(1) | XMM1 |
| 010 | DL | DX | EDX | MM2 / ST(2) | XMM2 |
| 011 | BL | BX | EBX | MM3 / ST(3) | XMM3 |
| 100 | AH | SP | ESP | MM4 / ST(4) | XMM4 |
| 101 | CH | BP | EBP | MM5 / ST(5) | XMM5 |
| 110 | DH | SI | ESI | MM6 / ST(6) | XMM6 |
| 111 | BH | DI | EDI | MM7 / ST(7) | XMM7 |

> 字长不断扩充、指令保持兼容，就是 IA-32 体系结构发展的轨迹。

### 3.2 80 位扩展精度格式（P39）

```text
 1位  s  | 15位 e（偏置 16383） | 1位 j（显式首位） | 63位 f（尾数）
```

- 与 IEEE 754 单/双精度的最大区别：**没有隐藏位**，首位 j 显式给出，有效位数共 64 位。
- 偏置常数 16 383 = 2^14 - 1。

### 3.3 x87 FPU 数据传送类指令（P40、P41）

| 指令 | 功能 |
|---|---|
| FLD | 将数据装入浮点寄存器栈顶 |
| FILD | 将 int 型数据转换为浮点格式后装入栈顶 |
| FSTx（x=s/l） | 将 ST(0) 转换为单/双精度后存入存储单元 |
| FSTPx | 弹出栈顶元素，并完成与 FSTx 相同的功能 |
| FISTx | 将栈顶数据从浮点格式转换为 int 后存入存储单元 |
| FISTPx | 弹出栈顶元素，并完成与 FISTx 相同的功能 |
| FXCH | 交换栈顶和次栈顶两个元素 |
| FLD1 / FLDZ | 装入常数 1.0 / 0.0 |
| FLDPI / FLDL2E / FLDL2T / FLDLG2 / FLDLN2 | 装入 π、log₂e、log₂10、log₁₀2、logₑ2 |

> **后缀规则**：带 P 表示操作数会出栈（ST(1) 变成 ST(0)）。

### 3.4 x87 FPU 算术运算类指令（P42、P43）

| 类别 | 指令 | 说明 |
|---|---|---|
| 加 | FADD/FADDP | 相加 / 相加后弹出 |
| 加 | FIADD | 按 int 型相加 |
| 减 | FSUB/FSUBP | 相减 / 相减后弹出 |
| 减 | FSUBR/FSUBRP | 调换次序相减（y−x）后弹出 |
| 减 | FISUB / FISUBR | 按 int 型相减 / 调换次序 |
| 乘 | FMUL/FMULP | 相乘 / 相乘后出栈 |
| 乘 | FIMUL | 按 int 型相乘 |
| 除 | FDIV/FDIVP | 相除 / 相除后出栈 |
| 除 | FDIVR/FDIVRP | 反序相除 |
| 除 | FIDIV / FIDIVR | 按 int 型相除 / 反序 |

> **后缀规则**：`P`=pop（出栈），`R`=reverse（操作数顺序反），`I`=int（先把整型转浮点）。若指令不带操作数，默认操作数是 ST(0) 和 ST(1)。

例如：`fidivl 0x8(%ebp)` 表示把 `M[R[ebp]+8]` 中的 int 转成 double，再用 ST(0) 除以它，结果存回 ST(0)。

### 3.5 SSE（SIMD）性能对比（P37、P38）

普通指令版本：

```asm
080484f0 <dummy_add>:
  push  %ebp
  mov   %esp, %ebp
  mov   $0x4000000, %ecx      # 循环 2^26 次
  mov   $0x1, %al
  mov   $0x0, %bl
L:add   %al, %bl              # 每次只加 1 个字节
  loop  L
  pop   %ebp
  ret
```

耗时约 **22.643816 s**。

SIMD 版本：

```asm
08048510 <dummy_add_sse>:
  push  %ebp
  ...
  mov   $0x400000, %ecx       # 循环 2^22 次
  movdqa (%eax), %xmm0        # 一次装入 16 字节（对齐）
  movdqa (%ebx), %xmm1
L:paddb %xmm0, %xmm1          # 16 个字节同时相加
  loop  L
  ...
  ret
```

耗时约 **1.411588 s**。

```text
2^26 个字节 ÷ 每次 16 字节 = 2^22 次循环
22.643816 s / 1.411588 s ≈ 16.04 ≈ 16（与 128/8=16 完全吻合）
```

> **结论**：SIMD 一条指令处理 128/8=16 个字节，理论加速比约 16 倍，实测与预期一致。`movdqa` 中的 dqa = double quadword aligned（两个对齐的四字），要求 16 字节对齐；`paddb` 是 packed add bytes（按字节打包相加）。

### 3.6 浮点经典坑：老版本 gcc 下 `a==b` 为什么输出 0（P44–P48）

两个程序：

```c
/* 程序一 */
double f(int x) { return 1.0 / x; }
void main() {
    double a, b; int i;
    a = f(10); b = f(10);
    i = a == b;
    printf("%d\n", i);
}

/* 程序二 */
double f(int x) { return 1.0 / x; }
void main() {
    double a, b, c; int i;
    a = f(10); b = f(10); c = f(10);
    i = a == b;
    printf("%d\n", i);
}
```

> 老版本 `gcc -O2` 编译时：程序一输出 **0**，程序二输出 **1**。为什么？

先看 `f` 的机器级代码：

```asm
f:
  push   %ebp
  mov    %esp, %ebp
  fld1                  # ST(0) ← 1.0
  fidivl 0x8(%ebp)      # ST(0) ← 1.0 / x（x87 内部 80 位精度）
  leave
  ret
```

`f(10) = 0.1`，而 0.1 的**二进制**表示是无限循环小数：

```text
0.1 = 0.0001100110011…B = 1.100110011…×2^-4
double 机器数：3FB999999999999Ah（无法精确表示，只能舍入）
```

**程序一**（a 存回内存，b 留在寄存器栈顶）：

```asm
  call f
  fstpl -8(%ebp)        # a 按 double(64位) 存回内存：80位 → 64位，发生舍入
  movl $0xa, (%esp)
  call f                # b = f(10)，结果仍以 80 位留在 ST(0)
  fldl  -8(%ebp)        # 把 a（64位）装入 ST(0)，b 变成 ST(1)
  pop   %eax            # 清理栈上参数（不影响比较）
  fucompp               # 比较 a 与 b，并弹出两者
  fnstsw %ax            # FPU 状态字送入 AX
  and   $0x45, %ah
  cmp   $0x40, %ah
  sete  %al             # 相等则 al = 1
```

比较时：**a 是舍入过的 64 位值，b 是未舍入的 80 位值** → 不相等 → 输出 0。

**程序二**（a、b 都存回内存，多算的 c 直接丢弃）：

```asm
  call f
  fstpl -8(%ebp)        # a：80位 → 64位，舍入
  movl $0xa, (%esp)
  call f
  fstpl -16(%ebp)       # b：80位 → 64位，舍入
  movl $0xa, (%esp)
  call f
  fstp  %st(0)          # c 丢弃
  fldl  -8(%ebp)        # 装入 a（64位 → 80位，精确）
  fldl  -16(%ebp)       # 装入 b（64位 → 80位，精确）
  fxch  %st(1)
  pop   %eax            # 清理栈上参数（不影响比较）
  fucompp               # 比较 a 与 b
```

比较时：**a、b 都是舍入过的 64 位值**，再装入 80 位是精确转换 → 相等 → 输出 1。

```text
80位 → 64位：可能产生舍入（丢失精度）
64位 → 80位：精确（double 是 80 位扩展的子集）
```

> **附：`fucompp` 结果怎么变成 0/1**
> FPU 状态字中 C0（bit8）、C2（bit10）、C3（bit14）表示比较结果；送入 AH 后分别对应 0x01、0x04、0x40。`and $0x45,%ah` 只保留这三位，`cmp $0x40` 判断"仅 C3=1"，即相等；`sete` 把它变成 0/1。

**这个例子说明**（P48）：

- 编译器的设计与硬件结构紧密相关；
- 编译器作者必须真正理解底层硬件和 ISA，才能翻译出正确的目标代码、为程序员屏蔽硬件细节；
- 应用程序员也只有了解底层硬件，才能写出高效程序，并在出错时快速定位、对程序行为作出正确判断。

## 4. 3.4 C 语言程序的机器级表示（上）（P50–P72）

### 4.1 过程调用概述（P52、P53）

- 程序员用**参数**把过程与其他程序、数据分离；
- 调用过程只要把输入参数传给被调用过程，最后由被调用过程把结果参数返回；
- 引入过程后，每个程序员只需关注本模块中函数/过程的编写；
- C 语言中，"过程"和"函数"是等价的。

以 `main` 调用 `add(t1,t2)` 为例，要回答三个问题：

1. 如何把 t1(125)、t2(80) 分别传给 add 的形参 x、y？
2. add 的执行结果如何返回给 caller？
3. 调用前后，寄存器和栈发生了什么变化？

> 为了统一，模块代码之间必须遵循**调用接口约定**（calling convention），具体由 **ABI**（应用二进制接口）规范定义，编译器强制执行，汇编语言程序员也必须遵守。这也解释了为什么 ISA 相同但 ABI 不同的程序（如 Windows 的 exe 与 Linux 的可执行文件）不能直接互跑。

### 4.2 可执行文件的存储器映像（P54）

```text
高地址 0xFFFFFFFF  ┌───────────────────┐
                   │   内核虚存区 (1GB) │
        0xC0000000 ├───────────────────┤
                   │ 用户栈（动态生成） │ ← ESP(栈顶)，向低地址增长
                   │   共享库区域       │
                   │   堆 heap         │ ← brk，向高地址增长
                   │ 读写数据段        │ (.data, .bss)
                   │ 只读代码段        │ (.init, .text, .rodata)
        0x08048000 ├───────────────────┤
低地址 0           └───────────────────┘
```

一个可执行文件从 ELF 头开始，依次包含程序（段）头表与各节：

| 节 | 内容 | 运行时去向 |
|---|---|---|
| .init / .text | 初始化代码、可执行指令 | 只读代码段 |
| .rodata | 只读数据（如字符串常量） | 只读代码段 |
| .data | 已初始化的全局/静态变量 | 读写数据段 |
| .bss | 未初始化（或初值为0）的全局/静态变量 | 读写数据段（不占文件空间） |
| .symtab / .debug / .line / .strtab | 符号表、调试信息 | 不装入内存 |

> IA-32 中**参数通过栈来传递**，所以先要搞清楚栈在哪：用户栈在用户空间的顶部，从高地址向低地址增长，ESP 指向栈顶。

### 4.3 过程调用的六个步骤（P55）

设 P 为调用者，Q 为被调用者：

| 阶段 | 步骤 | 谁来做 |
|---|---|---|
| 准备阶段 | ① P 将入口参数（实参）放到 Q 能访问到的地方 | P |
| 准备阶段 | ② P 保存返回地址，并将控制转移到 Q | P（CALL 完成） |
| 准备阶段 | ③ Q 保存 P 的现场，并为自己的非静态局部变量分配空间 | Q |
| 处理阶段 | ④ 执行 Q 的过程体（函数体） | Q |
| 结束阶段 | ⑤ Q 恢复 P 的现场，释放局部变量空间 | Q |
| 结束阶段 | ⑥ Q 取出返回地址，将控制转移到 P | Q（RET 完成） |

> **什么是"现场"**：通用寄存器的内容。**为什么要保存现场**：所有过程共享同一套通用寄存器，Q 用完不恢复，P 回来就"变样"了。

### 4.4 i386 System V ABI 的寄存器使用约定（P59）

| 类别 | 寄存器 | 约定 |
|---|---|---|
| 调用者保存 | EAX、EDX、ECX | 被调用者可直接使用，无需保存；**调用者**若在调用后还要用，必须自己先保存、返回后恢复 |
| 被调用者保存 | EBX、ESI、EDI | **被调用者**使用前必须保存到栈，返回前恢复 |
| 帧指针 / 栈指针 | EBP、ESP | EBP 指向当前栈帧底部（帧底），ESP 指向栈顶 |
| 返回值 | EAX（32 位）、EDX:EAX（64 位） | 返回参数总在 EAX 中 |

> **问题**：为了减少准备和结束阶段的开销，每个过程应优先使用哪些寄存器？
> **答**：EAX、ECX、EDX（调用者保存寄存器），因为它们不需要保存/恢复。用到 EAX 之外的被调用者保存寄存器就得付出压栈、出栈的代价。

### 4.5 栈和栈帧（P60、P61）

- IA-32 用栈支持过程的嵌套调用：入口参数、返回地址、被保存寄存器的值、非静态局部变量都压入栈；
- 栈从**高地址向低地址**增长，栈顶由 ESP 指示；
- 每个过程有自己的栈区，称为**栈帧**（stack frame），一个栈由若干栈帧组成；
- 每个栈帧用帧指针 EBP 指定起始位置：EBP 固定不动，ESP 随数据入栈动态移动，两者之间就是当前栈帧。

单个栈帧 + 调用时的变化：

```text
高地址
        ┌──────────────────────┐
        │ 调用者保存寄存器(必要时) │
        │ 参数 n                │
        │   ...                │
        │ 参数 1                │
        ├──────────────────────┤ ← 调用者的 ESP
        │ 返回地址 RA           │ ← CALL 压入
        ├──────────────────────┤
        │ 调用者的 EBP 旧值      │ ← EBP（当前栈帧底部）
        │ 被调用者保存寄存器      │
        │ 非静态局部变量          │
        │   ...                │ ← ESP（栈顶，动态变化）
低地址
```

过程调用过程中栈帧的变化（P61 的 ①→④）：

| 时刻 | 状态 |
|---|---|
| ① 调用前 | 只有调用者的栈帧，ESP 在调用者栈顶，参数尚未压入 |
| ② 压入参数 | 调用者把参数 n…1 依次压栈，ESP 下移，参数区就位 |
| ③ 执行 CALL | 返回地址入栈，控制转入被调用者，被调用者开始建自己的栈帧 |
| ④ 返回后 | Q 的栈帧被释放，ESP 回到调用者栈顶，局部变量失效 |

> 函数的局部变量只在**自己的栈帧**中有效，因此可以和其他函数的局部变量同名；外部参照型变量和静态变量分配在**静态数据区**，具有全局生存性。

### 4.6 过程（函数）的结构（P64）

```asm
; ===== 准备阶段 =====
pushl %ebp              ; ① 形成帧底：保存调用者的 EBP
movl  %esp, %ebp        ;    新的 EBP = 当前栈顶
subl  $N, %esp          ; ② 生成栈帧：为局部变量分配空间（N 与 EBP/RA 合计 16 字节对齐）
pushl %ebx              ; ③ 保存现场：如果用到被调用者保存寄存器

; ===== 过程体 =====
...                     ; 分配局部变量空间并赋值
...                     ; 具体处理逻辑
movl  ..., (%esp)       ; 遇到函数调用时：准备实参（第 1 个参数放栈顶）
call  func              ; 保存返回地址并转入被调用函数
...                     ; 使用 EAX 中的返回值
...                     ; 在 EAX 中准备返回参数

; ===== 结束阶段 =====
popl  %ebx              ; 恢复现场
leave                   ; 退栈：等价于 movl %ebp,%esp; popl %ebp
ret                     ; 取返回地址返回
```

### 4.7 实例剖析：caller() 调用 add()（P62、P65）

```c
int add(int x, int y) { return x + y; }

int caller() {
    int t1 = 125;
    int t2 = 80;
    int sum = add(t1, t2);
    return sum;
}
```

完整机器级代码：

```asm
caller:
  pushl  %ebp              # 保存调用者的 EBP（帧底）
  movl   %esp, %ebp
  subl   $24, %esp         # 分配 24 字节栈帧
  movl   $125, -12(%ebp)   # t1 = 125
  movl   $80,  -8(%ebp)    # t2 = 80
  movl   -8(%ebp),  %eax   # eax = t2
  movl   %eax, 4(%esp)     # 第 2 个实参 y（放在高地址）
  movl   -12(%ebp), %eax   # eax = t1
  movl   %eax, (%esp)      # 第 1 个实参 x（放在栈顶）
  call   add               # 返回地址入栈，转 add 执行
  movl   %eax, -4(%ebp)    # sum = add(...)，返回值在 EAX
  movl   -4(%ebp), %eax    # return sum
  leave
  ret

add:
  pushl  %ebp
  movl   %esp, %ebp
  movl   12(%ebp), %eax    # eax = y
  movl   8(%ebp),  %edx    # edx = x
  leal   (%edx,%eax), %eax # eax = x + y（lea 不影响标志）
  popl   %ebp
  ret
```

执行到 `call add` 之后、`add` 建立完栈帧时，栈的布局（以 caller 的 EBP 为基准）：

| 地址（相对 caller 的 EBP） | 内容 | 说明 |
|---|---|---|
| EBP+12 | 80（t2） | add 的第二个实参 y |
| EBP+8 | 125（t1） | add 的第一个实参 x |
| EBP+4 | 返回地址 RA | `call` 压入 |
| EBP | caller 的 EBP 旧值 | `pushl %ebp` 压入；也是 add 帧底 |
| EBP-4 | sum | 局部变量 |
| EBP-8 | t2 = 80 | 局部变量 |
| EBP-12 | t1 = 125 | 局部变量 |
| EBP-16 | 未使用 | 对齐填充 |
| EBP-20 | 80 | 准备给 add 的 y（即 `4(%esp)`） |
| EBP-24 | 125 | 准备给 add 的 x（即 `(%esp)`，此时 ESP=EBP-24） |

**为什么 `8(%ebp)` 是 x、`12(%ebp)` 是 y？**

```text
进入 add 时：call 已把 RA 压到栈顶
add 再 pushl %ebp（压入 caller 的 EBP），然后 movl %esp,%ebp
所以：  EBP+4 = RA，EBP+8 = 第一个参数 x，EBP+12 = 第二个参数 y
```

**几处细节**：

- `subl $24, %esp`：3 个局部变量（12 字节）+ 2 个实参（8 字节）= 20 字节，取 24 是为了对齐；算上保存的 EBP（4 字节）和返回地址（4 字节），整个栈帧 24+8=32 字节，是 16 的倍数。**每个非叶子过程的栈帧大小必须是 16 字节的倍数**，目的是保证调用时栈指针对齐（SSE 指令要求 16 字节对齐）。
- `movl %eax, 4(%esp)` 再 `movl %eax, (%esp)`：先放第 2 个参数到高地址，再放第 1 个参数到栈顶，最终**第 1 个参数在最低地址**。这就是"参数从右往左压栈"的效果。
- `leal (%edx,%eax), %eax` 实现 x+y：`lea` 只是"算地址"，不改变标志，比 `addl` 更轻量，这是编译器常见的优化。
- `leave` = `movl %ebp,%esp` + `popl %ebp`，一步完成"释放栈帧 + 恢复 EBP"。
- 栈中参数按 4 字节对齐：`(unsigned) char`、`(unsigned) short` 也都分配 4 个字节。

### 4.8 参数传递：按值 vs 按地址（P67–P69）

```c
/* 程序一：按地址传递 */
void swap(int *x, int *y) {
    int t = *x;
    *x = *y;
    *y = t;
}
void main() {
    int a = 15, b = 22;
    printf("a=%d\tb=%d\n", a, b);
    swap(&a, &b);
    printf("a=%d\tb=%d\n", a, b);
}

/* 程序二：按值传递 */
void swap(int x, int y) {
    int t = x;
    x = y;
    y = t;
}
void main() {
    int a = 15, b = 22;
    printf("a=%d\tb=%d\n", a, b);
    swap(a, b);
    printf("a=%d\tb=%d\n", a, b);
}
```

输出：

```text
程序一：a=15 b=22 → a=22 b=15   （交换成功）
程序二：a=15 b=22 → a=15 b=22   （没有任何变化）
```

**按地址传递的机器级代码**：

```asm
main:
  ...
  leal  -8(%ebp), %eax      # eax = &b
  movl  %eax, 4(%esp)       # 第 2 个实参 y = &b
  leal  -4(%ebp), %eax      # eax = &a
  movl  %eax, (%esp)        # 第 1 个实参 x = &a
  call  swap
  ...

swap:
  pushl %ebp
  movl  %esp, %ebp
  pushl %ebx                # EBX 是被调用者保存寄存器，先保存
  movl  8(%ebp),  %edx      # edx = &a
  movl  (%edx),   %ecx      # ecx = *x = 15      （t = *x）
  movl  12(%ebp), %eax      # eax = &b
  movl  (%eax),   %ebx      # ebx = *y = 22
  movl  %ebx, (%edx)        # *x = 22           （*x = *y）
  movl  %ecx, (%eax)        # *y = 15           （*y = t）
  popl  %ebx
  popl  %ebp
  ret
```

栈帧状态（main 中，call 之前）：

| 地址 | 内容 | 说明 |
|---|---|---|
| EBP-4 | a = 15 | `leal -4(%ebp)` 取得 &a |
| EBP-8 | b = 22 | `leal -8(%ebp)` 取得 &b |
| ... | ... | 中间是 main 的其他局部变量/对齐空间 |
| 4(%esp) | &b | swap 的第 2 个实参 y |
| (%esp)，此时 ESP | &a | swap 的第 1 个实参 x |

swap 通过指针真正改写了 main 栈帧里的 a、b：

```text
R[edx] ← &a，R[ecx] ← M[&a] = 15
R[eax] ← &b，R[ebx] ← M[&b] = 22
M[&a] ← R[ebx] = 22
M[&b] ← R[ecx] = 15
```

**按值传递的机器级代码**：

```asm
main:
  ...
  movl  -8(%ebp), %eax      # eax = b = 22
  movl  %eax, 4(%esp)       # y = 22（传的是值！）
  movl  -4(%ebp), %eax      # eax = a = 15
  movl  %eax, (%esp)        # x = 15
  call  swap
  ...

swap:
  pushl %ebp
  movl  %esp, %ebp
  movl  8(%ebp),  %edx      # edx = x = 15
  movl  12(%ebp), %eax      # eax = y = 22
  movl  %eax, 8(%ebp)       # x = 22（只改栈中的实参副本）
  movl  %edx, 12(%ebp)      # y = 15
  popl  %ebp
  ret
```

栈帧状态（main 中，call 之前）：

| 地址 | 内容 | 说明 |
|---|---|---|
| EBP-4 | a = 15 | 局部变量 |
| EBP-8 | b = 22 | 局部变量 |
| ... | ... | 中间是 main 的其他局部变量/对齐空间 |
| 4(%esp) | 22 | swap 的第 2 个实参 y（b 的副本） |
| (%esp)，此时 ESP | 15 | swap 的第 1 个实参 x（a 的副本） |

```text
R[edx] ← 15，R[eax] ← 22
M[R[ebp]+8]  ← 22
M[R[ebp]+12] ← 15
```

> **结论**：按值传递时，swap 交换的只是**入口参数的副本**，main 的局部变量 a、b 一点没变。按地址传递时，传进去的是地址，通过指针间接访问的才是 main 中的真变量。
> 另外注意：`swap` 用到了被调用者保存寄存器 EBX，所以入口 `pushl %ebx`、出口 `popl %ebx`，这就是"被调用者保存"的实际体现。

### 4.9 例3.9：多级过程调用中的参数传递（P70）

```c
void test(int x, int *ptr)
{
    if (x > 0 && *ptr > 0)
        *ptr += x;
}

void caller(int a, int y)
{
    int x = a > 0 ? a : a + 100;
    test(x, &y);
}
```

> 调用 caller 的过程为 P，P 中给形参 a、y 的实参分别是 100 和 200。画出相应栈帧状态，并回答：
> (1) test 的形参是按值传递还是按地址传递？test 的形参 ptr 对应的实参是什么类型的值？
> (2) test 中被改变的 `*ptr` 的结果如何返回给它的调用过程 caller？
> (3) caller 中被改变的 y 的结果能否返回给过程 P？为什么？

**① 执行 caller 之前，P 的栈帧（P 已把实参压好，CALL 已压入返回地址）：**

```text
高地址
  ┌──────────────────────────────┐
  │ ......（P 的栈帧内容）          │ ← EBP_P
  │ 200   caller 的形参 y 的实参    │
  │ 100   caller 的形参 a 的实参    │
  │ 返回地址（caller 返回 P）       │ ← ESP（CALL caller 已压入）
  └──────────────────────────────┘
低地址
```

**② 执行 test 之前（call 已压入返回地址），caller 的栈帧：**

```text
高地址
  ┌──────────────────────────────┐
  │ ......（P 的栈帧内容）          │
  │ 200   caller 的形参 y          │ ← EBP_caller+12
  │ 100   caller 的形参 a          │ ← EBP_caller+8
  │ 返回地址（caller 返回 P）       │ ← EBP_caller+4
  ├──────────────────────────────┤
  │ P 的 EBP 旧值                  │ ← EBP_caller（caller 帧底）
  │ ......（caller 的局部变量等）   │
  │ &y    test 的第 2 个实参        │
  │ 100   x，test 的第 1 个实参     │
  │ 返回地址（test 返回 caller）    │ ← ESP（CALL test 已压入）
  └──────────────────────────────┘
低地址
```

**③ 进入 test 并建立栈帧后：**

```text
高地址
  ┌──────────────────────────────┐
  │ ......                          │
  │ &y    （ptr）                   │ ← EBP_test+12
  │ 100   （x）                     │ ← EBP_test+8
  │ 返回地址（test 返回 caller）     │ ← EBP_test+4
  ├──────────────────────────────┤
  │ caller 的 EBP 旧值              │ ← EBP_test（test 帧底）
  │ test 的局部变量 / 对齐空间       │ ← ESP
  └──────────────────────────────┘
低地址
```

**解答：**

(1) **x 按值传递，ptr 按地址传递**。`ptr` 对应的实参是 `&y`，一定是一个**地址值**（int* 类型）。

(2) `test` 中 `*ptr += x` 把值 100 加到 `*ptr` 上。因为 `ptr = &y`，而 y 是 caller 的形参，它的存储单元在 caller 的入口参数区（即 EBP_caller+12，属于 P 的栈帧底部），所以 **P 帧中那个 200 变成了 300**。test 退帧后，caller 通过形参 y（保存的是地址）引用到该值 300，于是结果被带回 caller。

(3) **不能直接返回给 P**。第 11 行 `test(x,&y)` 执行完、caller 退帧返回 P 后，P 中没有任何变量与那个单元对应（P 只是把 100、200 作为实参值传了下去），因此 P 无法再引用这个 300。

> 若 `caller` 改为 `return x + y;`，则返回值为 100 + 300 = **400**。

### 5.2 高频考点与易错点

| 易错点 | 正确认识 |
|---|---|
| 用 CF 判断带符号溢出 | 带符号溢出看 **OF**，无符号进位/借位看 **CF** |
| 比较大小只会背 `jl/jg` | 无符号用 **jb/ja/jbe/jae**；带符号用 **jl/jg/jle/jge** |
| 认为 `>>1` 都是补 0 | 有符号数用 **sar**（补符号位），无符号数用 **shr**（补 0） |
| `i <= len-1` 中 len 为 unsigned | `len=0` 时 `len-1` 下溢成 0xFFFFFFFF，条件恒真 → 越界；改成 `i < len` 或 `int len` |
| 移位数大于 1 直接用立即数 | 若次数是变量，用 **CL** 指定 |
| 逻辑运算都会改标志 | **NOT 不影响标志** |
| 乘法结果只在一个寄存器 | 8 位在 AX；16 位在 DX:AX；32 位在 EDX:EAX |
| `lea` 与 `mov` 混淆 | `lea` 取**地址**，`mov` 取地址里的**内容**；`lea` 不改标志 |
| 参数顺序 | 第 1 个参数在**最低地址（栈顶）**，编译器从右往左准备 |
| 返回值位置 | 32 位在 **EAX**，64 位在 **EDX:EAX** |
| 调用者/被调用者保存搞反 | 调用者保存：EAX/EDX/ECX；被调用者保存：EBX/ESI/EDI |
| 栈帧大小 | 必须是 **16 字节的倍数**（含保存的 EBP 与返回地址） |
| 浮点数直接 `==` | 80 位寄存器与 64 位内存之间来回转换可能舍入，`a==b` 结果可能"反直觉" |
| 转移目标是绝对地址 | 相对寻址：目标 = **下一条指令地址 + 符号扩展偏移** |
