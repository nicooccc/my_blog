## 端口号

- TCP/IP体系的应用进程用端口号来区分不同进程
- 取值 0 - 65535

0 - 1023： TCP/TP中重要的应用协议：FTP 21/20 HTTP 80 DNS 53

- 1024 - 49151：在IANA登记的应用程序使用
- 49152 - 65525： 为用户的进程暂时使用

## 复用和分用

发送方：不同进程的应用报文通过UDP和TCP的端口转化为UDP数据报和IP报文段

再在网络层中经过IP复用封装成IP数据报，区别在于报文中的协议字段

接收方：在网络层中根据IP数据报中的不同的协议字段分用转到运输层不同的端口进行分用

## UDP与TCP的对比

![image-63](../../../../assets/images/计算机网络/image-63.png)

- UDP（user datagram Protocol） //无连接的
- 支持一对多，一对一，多对一

TCP（transmission control protocol）  //面向连接的

支持单播

![image-64](../../../../assets/images/计算机网络/image-64.png)

UDP是面向应用报文的

TCP是面向字节流的（TCP不保证一次传完，这就要求应用进程有能力处理乱序和多次传输后拼接完整）//来实现可靠传输，流量控制，拥塞控制 // 全双工通信

![image-65](../../../../assets/images/计算机网络/image-65.png)

UDP向上提供的是无连接不可靠的传输服务 //出现误码和丢失的问题UDP不关心

TCP提供的面向连接的可靠传输服务 //不会出现传输差错

## TCP流量控制

- 让发送方的发送速率不要太快，让接收方来的及接受
- 利用滑动窗口机制实现Flow Control

![image-68](../../../../assets/images/计算机网络/image-68.png)

- 接收方的窗口由本身情况调整
- 当接收窗口为0时，接收方启动一个0窗口计时器
- 若计时器超时则发送一个o窗口探测报文（1字节）
- 0窗口计时器也有重传计时器
- 接收方对0报文进行并进行确认，通告当前的接受窗口大小

![image-69](../../../../assets/images/计算机网络/image-69.png)

### TCP连接释放  
通过四报文挥手  
先是一方的单向进行释放连接  
接着另一方的进行释放连接

| 特性       | **ACK** (标志位)          | **ack** (确认号)                 |
| -------- | ---------------------- | ----------------------------- |
| **全称**   | Acknowledgment Flag    | Acknowledgment Number         |
| **本质**   | TCP首部中的一个**控制位**       | TCP首部中的一个**32位字段**            |
| **大小**   | 1bit                   |                               |
| **作用**   | 一个**开关**，指示“确认号”字段是否有效 | 一个**数值**，告诉对方“我期望收到的下一个字节的序号” |
| **取值**   | `0` 或 `1`              | 一个32位的无符号整数                   |
| **依赖关系** | **主动**：决定ack字段是否被解读    | **被动**：其含义生效与否，完全取决于ACK位是否为1  |

 
 
 一方发送tcp释放报文  FIN=1 ACK= 1 seq=u（已传送的最后序号加一） ack=v同时对之前确认(不携带数据)

另一方发送 普通确认报文段 ACK=1 seq=v（tcp进程之前一传送的数据的最后一个字节加一） ack = u+1

通知应用进程关闭  
tcp服务进程到tcp客户进程没有关闭，相反的关闭了  
所以tcp服务器进程还可以发送数据  


tcp服务器发送释放报文 FIN=1 ACK=1 seq=w ack=u+1释放报文  
客户端发送普通的tcp确认报文 ACK=1 seq=u+1 ack=w+1（不传输数据，但是消耗数据）

## TCP报文首部格式 
TCP是面向字节流的  
发送数据中时，从发送缓存取出一部分成为tcp报文段
由 **首部** 和**数据载荷** 构成
功能体现在首部个字段

![Pasted image 20261110212803](../../../../assets/images/根目录/Pasted%20image%2020261110212803.png)
目的端口：代表什么协议，80是http，由应用层解析后走向不同的主机进程
![Pasted image 20261111084606](../../../../assets/images/根目录/Pasted%20image%2020261111084606.png)
序号：携带数据载荷的第一个序号
确认号：期望收到下一个数据载荷的序号（n之前的数据都接受了），只有ACK等于1是才有效
TCP规定建立连接后所有tcp的ACK都要是1
为什么有序号和确认号？TCP是全双工

FIN：用来释放TCP连接


RST：用来复位TCP连接，RST=1时，tcp连接出现了异常，必须释放连接，如何重新建立连接 ，还可以用来拒绝一个非法的报文端或者拒绝打开一个tcp连接 

PSH：接收方收到该标志为1时会尽快上交应用进程，不等到填满后在交付
