# 程序和指令执行的概述
- 程序是由一条条指令组成
- 按顺序存放在连续的储存单元内

正常情况，指令按存放顺序一条一条执行

需要转移的是，使用相应的转移指令  PC = PC + “1”（这条指令的长度）

用程序计数器PC保存将要执行指令的存储地址

通过改变PC的值来控制指令的执行顺序
PC：program counters
EIP：Instruction Point
**周期**

指令周期：（最长）
取出并执行一条指令的时间
机器周期（CPU周期、取指周期）：
完成一个基本操作（如取出一条指令）所需的时间
时钟周期（振荡周期）：（最小）
时钟频率的倒数，是计算机中最基本最小的时间单位，在一个时钟周期内CPU仅完成一个基本动做


# 执行过程

大致分为
**取指令、指令译码、计算源操作数地址并取操作数、执行数据操作、计算目的操作数地址并存结果、计算下调指令地址**


基本操作实现

1. **取指**：从 PC 所指内存取出指令送 IR，取“最长指令字节数”。
2. **译码**：根据不同指令译出不同控制信号。
3. **取操作数**：根据寻址方式确定源/目的操作数地址，访存或读寄存器。
4. **执行**：由 ALU 或加法器完成运算，计算目的地址。
5. **回写**：把结果写回寄存器或主存。
6. **修改 PC**：顺序则 PC + 当前指令长度，转移则把目的地址写入 PC

CPU上电后，读出PC中所指的存储单元并执行，因为每次执行都会改变PC值，因此CPU可以一直执行命令

| 类别           | 来源             | 典型例子                                            |
| ------------ | -------------- | ----------------------------------------------- |
| 内部异常         | CPU 内部         | 非法操作码、段错误/缺页、ALU 溢出、除数为 0、断点、单步跟踪；硬故障中断（硬件线路异常） |
| 外部中断（I/O 中断） | CPU 外部 I/O 子系统 | 采样计时到、网络包到达、磁盘读写完成                              |

- CPU 必须具备打断时的处理机制，称为**异常控制 / 中断机制**，相应处理逻辑叫**中断机构**。
- 外部中断的处理：**每条指令执行完 CPU 主动查询中断请求** → 有则把下条指令作为**断点**保存 → 转去执行“中断服务程序” → 结束后返回断点继续。这类事件与当前指令无关。

两类逻辑元件
组合逻辑元件（操作元件）:加法器 Adder、译码器 Decoder、多路选择器 MUX、ALU-------输出只取决于当前输入；**不受时钟控制**；输入一样输出一样；经门延迟后改变并保持

时序逻辑元件（状态/存储元件）:D 触发器、寄存器、存储器------**有存储功能**；输入状态在时钟控制下被写入并保持到下一时钟；输出随时可读'

触发方式：上升沿触发、下降沿触发、双边沿触发。**边沿触发**是现代寄存器最常用方式。

元件间连接方式：**总线连接** / **分散（专用线）连接**。

数据通路 = 操作元件 + 存储元件经总线或分散方式连接，完成数据的存储、处理与传送。

**总线式数据链路**

早期最简单的分散连接IAS计算机：`PC→MAR, Read M, M→MBR→IBR→IR`


单总线
四种基本操作的时序控制信号（标记为 L2，即在第 2 级/一个总线周期完成一步）：

| 基本操作   | 控制信号序列                                          | 周期数       |
| ------ | ----------------------------------------------- | --------- |
| 寄存器间传送 | `R0out, Yin`                                    | 1 Cycle   |
| 算术逻辑运算 | `R1out, Yin` → `R2out, Add, Zin` → `Zout, R3in` | 3 Cycles  |
| 从主存取字  | `R1out, MARin` → `Read, WMFC` → `MDRout, R2in`  | >3 Cycles |
| 写字到主存  | `R1out, MARin` → `R2out, MDRin` → `Write, WMFC` | >3 Cycles |
|        |                                                 |           |

WMFC = Wait for Memory Function Complete早期访存用**异步**方式，靠 MFC 应答信号；现代用**同步**方式，无需应答。单总线一个时钟只能传一个数据，效率很低。

#### ③ 三总线数据通路（第 32 页）

- 总线 A、B 分别传两个源操作数，总线 C 传结果；三条总线各传不同数据不冲突，**因此不再需要暂存器 Y 和 Z**。
- 采用双口通用寄存器组，实现 `R[R3] ← R[R1] op R[R2]` 只需一个控制信号序列 `R1outA, R2outB, op, R3inC`，**一个时钟周期即可完成**。

# 指令系统

**CISC**复杂，**RISC**精简

- **指令长度尽量一致**——简化取指与译码。MIPS 定长 32 位，下址计算方便（PC+4）；x86 长度 1~17 字节不等，取指部件极其复杂。
- **格式少、源寄存器位置相同**——指令未知时就能取操作数。MIPS 的 rs、rt 位置固定，译码时即可读出；若位置随指令变化，须先判明类型才能取寄存器编号。
- **只有 load/store 指令访存**——减少操作步骤、规整流水线。MIPS 的 lw/sw 地址计算与运算指令步骤规整在同一周期；x86 运算类指令操作数可为内存数据，需额外算地址、访存、执行。
- **内存中对齐存放**——减少访存次数，利于流水线规整。


| 对比项  | CISC（复杂指令集）                                    | RISC（精简指令集）                     |     |
| ---- | ---------------------------------------------- | ------------------------------- | --- |
| 指令系统 | 指令多、寻址方式多、格式多、变长操作码/指令字                        | 指令少、寻址方式少、格式少、**指令长度一致**        |     |
| 访存方式 | 各种指令都能访存（含运算指令），指令周期差距大                        | **RR 方式**：除 Load/Store 外都只访问寄存器 |     |
| 指令周期 | 长，多数指令需多个时钟周期                                  | 短，流水线工作，简单指令一个周期甚至不到            |     |
| 控制器  | 指令太复杂无法硬连线，只能用慢速微程序控制器                         | **硬连线控制器**，不用或少用微程序             |     |
| 其他   | 难编译优化；研制周期长、难调试维护（如 VAX-11/780：16 种寻址、303 条指令） | 大量通用寄存器减少访存；优化编译系统支持高级语言        |     |
