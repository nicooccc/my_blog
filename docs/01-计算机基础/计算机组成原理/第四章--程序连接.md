# 符号


	每一个可重定向的目标模块m都有一个符号表，包含在m中定义的符号


- **Global symbols 全局符号**：由模块 m 定义、能被其他模块引用。例如非 static 的函数和非 static 的全局变量（如 main.c 里的 buf）。
- **External symbols 外部符号**：由其他模块定义、被模块 m 引用。例如 main.c 里的函数名 swap。
- **Local symbols 本地符号**：仅由模块 m 定义和引用，例如带 static 的函数和全局变量（如 swap.c 里的 bufp1）

# 重定向与动态连接


## 重定向

合并相同的节：
将集合E的所有目标模块中的相同节，合并成新节
	所有的.text节合并成可执行文件中的.text节

对定义符号进行重定位（确定地址）

确定新节中所有定义符号在虚拟地址空间中的地址

   例如，为函数确定首地址，进而确定每条指令的地址，为变量确定首地址

完成这一步后，每条指令和每个全局变量都可确定地址

对引用符号进行重定位（修改引用）

–修改.text节和.data节中对每个符号的引用（地址）

   需要用到在.rel_data和.rel_text节中保存的重定位信息

## 动态连接

1. 库函数（如 printf）被包含进**每个运行进程**的代码段——上百个进程并发时，主存里就有上百份 printf，极大浪费内存；
2. 库函数被合并进每个可执行文件——磁盘上几千个可执行文件各带一份，极大浪费磁盘；
3. 库更新困难——程序员要关注新版本、下载、重新编译链接，使用不便。

解决方案:共享库，它也是一个含代码数据的目标文件，但**从程序中分离出来，磁盘和内存中都只有一份备份**，可以动态地在装入时或运行时加载链接。Windows 叫动态链接库 .dll，Linux 叫动态共享对象 .so

两种方式：
	装入时连接：第一次加载并运行时进行，Linux 通常由动态链接器 `ld-linux.so` 自动处理，标准 C 库 libc.so 通常按这种方式；
	运行时连接：程序已经开始运行后进行，Linux 通过 `dlopen()` 等接口实现，用于分发软件包、构建高性能 Web 服务器等。


位置无关代码（PIC），共享库代码就是个PIC：位置不确定，长度变化不影响调用的程序，目的：无需修改代码，就能加载任意地址运行
