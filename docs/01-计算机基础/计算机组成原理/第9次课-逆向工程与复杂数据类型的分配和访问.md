## 第一部分：3.6 C语言程序的机器级表示（下）

### 1. 逆向工程（P3–P9）

#### 1.1 什么是逆向工程（P4）

课件给出三个典型场景：

| 场景 | 说明 |
|---|---|
| 从可执行程序还原出 C 语言代码 | 编译的**逆过程**：机器码 → 汇编码 → C 代码 |
| 软件破解 | 分析授权/校验逻辑（但这不是课程目的） |
| 木马、病毒等恶意代码分析 | 安全分析、取证 |

**基本方法论**（本课 P5–P8 三个例子就是这套方法）：

1. 先看**过程序言/结束代码**（`pushl %ebp` / `movl %esp,%ebp` / `subl $x,%esp` / `leave` / `ret`），确定参数个数、栈帧大小、局部变量；
2. 再看 **`call`**，确定调用了哪些函数、传了几个参数；
3. 再看 **`jmp` / `Jcc`**，确定是 if-else 还是循环、判断条件是什么；
4. 再看 **`lea` 与各种寻址方式**，确定数据的类型、数组元素大小、结构体偏移；
5. 最后按"**一条 C 语句通常对应多条机器指令**"的粒度组装回 C 代码。

#### 1.2 逆向举例：过程调用（P5）

**题目**：已知 C 函数原型与机器级代码，回答问题。

```c
void func(int *xptr, int *yptr, int *zptr);
```

```asm
movl  8(%ebp),  %eax        # eax = xptr
movl  12(%ebp), %ebx        # ebx = yptr
movl  16(%ebp), %ecx        # ecx = zptr
movl  (%ebx),   %edx        # edx = *yptr
movl  (%ecx),   %esi        # esi = *zptr
movl  (%eax),   %edi        # edi = *xptr
movl  %edi, (%ebx)          # *yptr = *xptr
movl  %edx, (%ecx)          # *zptr = *yptr
movl  %esi, (%eax)          # *xptr = *zptr
```

**问题（1）三个入口参数对应的实参存放的存储单元地址是什么？**

答：分别是 **`EBP+8`、`EBP+12`、`EBP+16`**。

推理链条：
- 当前帧底由 `EBP` 指向，`EBP+0` 是旧 EBP、`EBP+4` 是返回地址（`CALL` 压入）、`EBP+8` 起才是参数；
- **IA-32 参数从右往左传**，先传 `zptr`（地址最大）、再 `yptr`、最后 `xptr`；
- 所以 `xptr` 在 `EBP+8`，`yptr` 在 `EBP+12`，`zptr` 在 `EBP+16`。**最右边参数的地址最大**。

**问题（2）根据机器级代码写出 C 代码**

```c
void func(int *xptr, int *yptr, int *zptr)
{
    int tempx = *xptr;
    int tempy = *yptr;
    int tempz = *zptr;
    *yptr = tempx;          /* y ← x 的原值 */
    *zptr = tempy;          /* z ← y 的原值 */
    *xptr = tempz;          /* x ← z 的原值 */
}
```

**要点**：这是"三个指针目标的值**循环移位**"——最终 `(x, y, z) = (z, x, y)`。注意汇编是**先把三个值全读进寄存器、再统一写回**（`edx/esi/edi`），否则 `*yptr=*xptr` 会破坏后面要用的 `*yptr` 旧值。这类"先读后写"的顺序是编译器自动保证的，写 C 时靠临时变量实现。

#### 1.3 逆向举例：分支判断（P6）

**题目**：给了 C 代码框架（留空）与对应汇编码，要求填空。

```asm
    movl  8(%ebp),  %eax        # eax = x
    movl  12(%ebp), %edx        # edx = y
    cmpl  $-100, %eax           # x 与 -100 比较
    jg    .L1                   # 若 x > -100 → 走 else-if 分支
    cmpl  %eax, %edx            # y 与 x 比较
    jle   .L2                   # 若 y <= x → .L2
    addl  %edx, %eax            # z = x + y
    jmp   .L3
.L2:
    subl  %edx, %eax            # z = x - y
    jmp   .L3
.L1:
    cmpl  $16, %eax             # x 与 16 比较
    jl    .L4                   # 若 x < 16 → .L4
    andl  %edx, %eax            # z = x & y
    jmp   .L3
.L4:
    imull %edx, %eax            # z = x * y
.L3:
```

**填空答案**：

```c
int func(int x, int y)
{
    int z = x * y;                      /* ① 默认值：对应 .L4 的 imull */
    if (x <= -100) {                    /* ② 由 jg .L1 反推：x<=-100 时进入此分支 */
        if (y > x)                      /* ③ 由 jle .L2 反推（y<=x 才跳走） */
            z = x + y;                  /* ④ */
        else
            z = x - y;                  /* ⑤ */
    } else if (x >= 16)                 /* ⑥ 由 jl .L4 反推（x<16 才跳走） */
        z = x & y;                      /* ⑦ */
    return z;
}
```

**反推技巧（重点）**：**Jcc 的"取反"就是 C 里的条件**。

| 汇编码 | 含义 | 对应 C 条件 |
|---|---|---|
| `jg .L1`（x > -100 才跳） | 跳走表示"不进入该 if 体" | `if (x <= -100)` |
| `jle .L2`（y <= x 才跳） | 跳走表示"不执行 then" | `if (y > x)` |
| `jl .L4`（x < 16 才跳） | 跳走表示"不执行 then" | `else if (x >= 16)` |

> `$16`、`$-100` 里的 `$` 就是"立即数"，十进制直接写；带符号数用 `jg/jl`（`SF`、`OF`），无符号数才用 `ja/jb`。

#### 1.4 逆向举例：循环结构（P7）

```asm
    movl  8(%ebp), %ebx         # ebx = x（入口参数）
    movl  $0, %eax              # eax = result = 0
    movl  $0, %ecx              # ecx = i = 0
.L12:
    leal  (%eax,%eax), %edx     # edx = 2*result（用 LEA 实现左移一位）
    movl  %ebx, %eax            # eax = x
    andl  $1, %eax              # eax = x & 0x01
    orl   %edx, %eax            # eax = 2*result | (x & 1)
    shrl  %ebx                  # x >>= 1（逻辑右移）
    addl  $1, %ecx              # i++
    cmpl  $32, %ecx             # i 与 32 比较
    jne   .L12                  # i != 32 则继续循环
```

**填空答案**：

| 空号 | 答案 | 依据 |
|---|---|---|
| ① | `i = 0` | `movl $0, %ecx` |
| ② | `i != 32` | `cmpl $32,%ecx` + `jne`（是**不等**而不是小于） |
| ③ | `i++` | `addl $1, %ecx` |
| ④ | `result = (result<<1) \| (x & 0x01); x >>= 1;` | 第 1、5、6、7、8 条指令 |

**补全后的 C 代码**：

```c
int function_test(unsigned x)
{
    int result = 0;
    int i;
    for (i = 0; i != 32; i++) {
        result = (result << 1) | (x & 0x01);
        x >>= 1;
    }
    return result;
}
```

**函数功能（自己多想一步）**：每轮把 `x` 的最低位"接"到 `result` 的最低位，再把 `result` 整体左移。32 轮之后 `result` 就是 `x` 的 **32 位二进制位序完全反转**（bit-reversal）。例如 `x = 0x00000001` → `result = 0x80000000`。

**其他信息**：
- 该函数**只有 1 个参数**，存在 `EBX` 里（不是 `EBP+8` 直接用，编译器常把参数搬进寄存器）；
- 返回值 `result` 在 `EAX` 里（这是 ABI 规定）；
- 处理结构是**循环结构**（`jne` 往回跳）；
- `leal (%eax,%eax), %edx` 是"用 LEA 做 2 倍"的经典技巧——LEA 不算数据、只算地址，不占 ALU 资源，也不影响标志位；
- `shrl` 是**逻辑右移**，说明 `x` 是**无符号数**；有符号数应看到 `sarl`。

#### 1.5 逆向举例：栈帧（P8）

**题目**：给了 C 代码与汇编码、初始寄存器值和 `.LC0` 地址，问执行若干条指令后 `EBP`、`ESP` 的值，以及局部变量 `x`、`y` 的地址。

```c
#include <stdio.h>
int funct(void)
{
    int x, y;
    scanf("%d,%d", &x, &y);
    return x - y;
}
```

```asm
 1  funct:
 2      pushl   %ebp
 3      movl    %esp, %ebp
 4      subl    $40, %esp          # 分配 40 字节局部区（十进制 40）
 5      leal    -8(%ebp), %eax     # eax = &y
 6      movl    %eax,  8(%esp)     # 8(%esp) = &y（最右边参数先入栈）
 7      leal    -4(%ebp), %eax     # eax = &x
 8      movl    %eax,  4(%esp)     # 4(%esp) = &x
 9      movl    $.LC0, (%esp)      # (%esp) = "%d,%d" 的指针（0x804c000）
10      call    scanf              # 假定 scanf 执行后 x=15, y=20
11      movl    -4(%ebp), %eax     # eax = x
12      subl    -8(%ebp), %eax     # eax = x - y
13      leave                      # = movl %ebp,%esp; popl %ebp
14      ret
```

**初始条件**：`R[esp] = 0xbc000020`，`R[ebp] = 0xbc000030`，`$.LC0 = 0x804c000`。

**逐条推演 `EBP` / `ESP`**：

| 时刻 | EBP | ESP | 说明 |
|---|---|---|---|
| 刚进入 `funct` | 0xbc000030 | 0xbc000020 | 调用者状态 |
| 执行第 2 条（`pushl %ebp`）后 | 0xbc000030 | 0xbc00001c | `push` 使 `ESP-4`，同时把旧 EBP(0xbc000030) 写入 0xbc00001c |
| 执行第 3 条（`movl %esp,%ebp`）后 | **0xbc00001c** | 0xbc00001c | 帧底建立 |
| 执行第 4 条（`subl $40,%esp`）后 | 0xbc00001c | **0xbbfffff4** | 0xbc00001c − 40(十进制) = 0xbbfffff4 |
| 第 5–9 条 | 不变 | 不变 | 只写栈单元，不改 `ESP` |
| 执行第 10 条 `call` 期间 | 不变 | 0xbbfffff0 | `CALL` 压入返回地址（−4），返回后弹回 |
| 执行第 10 条之后 | 0xbc00001c | **0xbbfffff4** | 返回地址已弹出 |
| 执行第 13 条（`leave`）后 | **0xbc000030** | **0xbc000020** | `movl %ebp,%esp` 再 `popl %ebp`，完全恢复 |

**三个问题的答案**：

1. 执行第 3、10、13 条后 `EBP` = **0xbc00001c、0xbc00001c、0xbc000030**
2. 执行第 3、10、13 条后 `ESP` = **0xbc00001c、0xbbfffff4、0xbc000020**
3. 由第 5–8 条指令知：`x` 在 `R[ebp]-4 = 0xbc000018`，`y` 在 `R[ebp]-8 = 0xbc000014`

**本帧的存储布局**：

```text
高地址  0xbc000030  ← 调用者的 EBP 值（旧 EBP 写在 0xbc00001c）
        0xbc000020  ← 返回地址（当前帧 [EBP+4]）
        0xbc00001c  ← EBP（帧底）
        0xbc000018  ← x  = [EBP-4]
        0xbc000014  ← y  = [EBP-8]
        ……（40 字节局部区中的其他部分无用/未用）
        0xbbfffffc  ← &y（即 8(%esp)）
        0xbbfffff8  ← &x（即 4(%esp)）
        0xbbfffff4  ← "%d,%d" 指针（即 (%esp)，当前 ESP）
低地址
```

**易错点提醒**：
- `0xbc00001c − 40` 是**十进制 40（0x28）**，不要看成 `0x40=64`；
- `4(%esp)`、`8(%esp)` 是**按"当前 ESP"算的**，而 `-4(%ebp)` 是按 **EBP** 算的；`subl` 之后两者指向完全不同的区域；
- `call` 期间 `ESP` 会临时再降 4（压返回地址），但 `call` 返回后恢复，所以"第 10 条执行后"的 `ESP` 是 0xbbfffff4 而不是 0xbbfffff0。

#### 1.6 逆向工程小结（P9）

1. 逆向工程就是**从可执行程序（机器级代码）还原出 C 语言代码**；
2. 逆向工程的目的是为了**学习与防范**，而不是破解；
3. 技术是把双刃剑，需要在遵循相关法律法规的前提下发挥其积极作用（**思政**）。

### 2. 二进制炸弹初探（P10–P16）

#### 2.1 实验介绍与评分标准（P11、P16）

"二进制炸弹"是一个**可执行的挑战程序**：它由 6 个关卡（`phase_1` … `phase_6`）组成，每关要求输入一个特定字符串/数字序列，答错就调用 `explode_bomb` 让程序"爆炸"（打印失败信息并退出）。你要做的正是**逆向工程**：用 `objdump` 反汇编 + `gdb` 调试，把每关的答案找出来。

**评分标准（附表 1-2）**：

| 破解进度 | 赋分 |
|---|---|
| 破解关卡 1–6 和隐藏关卡 | 100 |
| 破解关卡 1–6 | 90 |
| 破解关卡 1–5 | 80 |
| 破解关卡 1–4 | 70 |
| 破解关卡 1–3 | 55 |
| 破解关卡 1–2 | 40 |
| 破解关卡 1 | 20 |
| 未破解关卡 | 0 |

**各关卡考查的机器级分析能力**：

| 关卡 | 考查内容 |
|---|---|
| 1 | 字符串比较机器级程序的执行过程和执行结果分析能力 |
| 2 | 循环机器级程序的执行过程和执行结果分析能力 |
| 3 | 条件分支机器级程序的执行过程和执行结果分析能力 |

| 5 | 数组、指针机器级程序的执行过程和执行结果分析能力 |
| 6 | 链表机器级程序的执行过程和执行结果分析能力 |
| （隐藏）7 | 二叉树机器级程序的执行过程和执行结果分析能力 |

> 注意：**每位同学的炸弹均不同**（关卡答案随学号/身份而变化），所以答案不能抄，只能自己逆向。截止时间 **12 月 31 日**。

#### 2.2 反汇编（P12）

实验在线评测地址：`http://10.5.12.200:65535`

```bash
objdump -D -s bomb > obj
#   -D：反汇编目标文件中的【所有 section】（而不只是代码段）
#   -s：显示各个 section 的十六进制内容及对应的 ASCII 码
```

- 用 `-s` 输出的 ASCII 列，**常常能直接看到字符串常量**（如第一关的答案）；
- 用 `-D` 输出的代码段，能看到 `phase_n` 各关的完整指令流；
- 配合 `gdb` 的 `x/s 地址`、`x/8xb 地址` 可以进一步看内存内容。

#### 2.3 第一关——字符串比较（P13）

```asm
08048ae0 <phase_1>:
 8048ae0:  83 ec 1c         sub    $0x1c,%esp
 8048ae3:  c7 44 24 04 10 a0 04 08   movl  $0x804a010,0x4(%esp)   # 第 2 个参数 = 常量地址
 8048aeb:  8b 44 24 20      mov    0x20(%esp),%eax              # 取第 1 个参数（用户的输入串）
 8048aef:  89 04 24         mov    %eax,(%esp)                  # 第 1 个参数
 8048af2:  e8 43 04 00 00   call   8048f3a <strings_not_equal>
 8048af7:  85 c0            test   %eax,%eax                    # 返回 0 表示"相等"
 8048af9:  74 05            je     8048b00 <phase_1+0x20>       # 相等 → 通过
 8048afb:  e8 45 05 00 00   call   8049045 <explode_bomb>       # 不相等 → 爆炸
 8048b00:  83 c4 1c         add    $0x1c,%esp
 8048b03:  c3               ret
```

**分析**：

1. 没有 `push`，而是先 `sub $0x1c` 一次性预留参数区，再往里写——所以要访问入口参数要用 **`0x1c+4 = 0x20(%esp)`**（`sub` 之前是 `4(%esp)`）。**这是"用 ESP 相对寻址访问入口参数"时的常见坑**；
2. 调用了 `strings_not_equal`，返回 0 表示两串相等，所以答案是**地址 0x804a010 处的那串字符**；
3. 这个常量地址落在只读数据段 `.rodata`，用 `objdump -s` 直接 dump 出来看 ASCII 列即可。

**数据区 dump（0x804a008 开始）**：

```text
804a008 6973206f 6e652e00 4372696b 65792120  is one..Crikey!
804a018 49206861 7665206c 6f737420 6d79206d  I have lost my m
804a028 6f6a6f21 006f696c 65727300 9d8b0408  ojo!.oilers.....
```

逐字节解码：`0x804a010` 起是 `43 72 69 6b 65 79 21 20 49 20 68 61 76 65 20 6c 6f 73 74 20 6d 79 20 6d 6f 6a 6f 21 00`，即：

| 地址 | 字符串 |
|---|---|
| `0x804a008` | `"is one."`（上一条字符串的尾部） |

## 第二部分：3.7 复杂数据类型的分配和访问（上）

### 4. 数组的分配和访问（P19–P34）

#### 4.1 数组的基本概念（P20）

| 性质 | 说明 |
|---|---|
| 有序数据集合 | 数组元素在内存中**连续、按序**存放 |
| 元素同类型 | 每个元素属于**同一个数据类型** |
| 统一命名 | 用统一的**数组名 + 下标**唯一确定元素 |
| 大小静态确定 | C 语言**不允许对数组大小作动态定义**（长度必须是编译期可确定的常量，C99 的变长数组是后来的扩展） |
| 支持多维 | 一维、二维甚至高维数组 |

#### 4.2 数组元素的寻址方式（P21）

**核心公式**：设数组元素大小为 `size`（字节），首地址为 `SA = &A[0]`，则

```text
&A[i] = SA + size * i          （i = 0,1,2,…）
A[i]  = M[ SA + size * i ]     （读出该地址处的一个元素）
```

**例 1**：`static short A[4];`（`short` 占 2 字节）→ `&A[i] = &A[0] + 2*i`。

若 `&A[0]` 在 `EDX` 中、`i` 在 `ECX` 中，要把 `A[i]` 取到 `AX` 中：

```asm
movw  (%edx, %ecx, 2), %ax
```

- `%edx`：**基址寄存器**（数组首址）
- `%ecx`：**变址（索引）寄存器**，在循环体中增量
- `2`：**比例因子（scale）**，等于元素大小
- `movw`：因为 `short` 是 16 位，所以用 `w` 后缀写 `%ax`

见下表（P21/P26 反复出现的核心表）：

| 数组定义 | 数组名 | 元素类型 | 元素大小(B) | 数组大小(B) | 起始地址 | 元素 i 的地址 |
|---|---|---|---|---|---|---|
| `char S[10]` | S | `char` | 1 | 10 | `&S[0]` | `&S[0]+i` |
| `char *SA[10]` | SA | `char *` | 4 | 40 | `&SA[0]` | `&SA[0]+4*i` |
| `double D[10]` | D | `double` | 8 | 80 | `&D[0]` | `&D[0]+8*i` |
| `double *DA[10]` | DA | `double *` | 4 | 40 | `&DA[0]` | `&DA[0]+4*i` |

> **注意**：`SA`、`DA` 是**指针数组**——元素本身是指针，在 IA-32 下指针一律 **4 字节**，与它指向什么类型无关。所以 `&SA[0]+4*i` 而不是 `+i`。这是最容易被问倒的一类题。

#### 4.3 静态区数组的存放和访问（P22）

```c
int buf[2] = {10, 20};
int main()
{
    int i, sum = 0;
    for (i = 0; i < 2; i++)
        sum += buf[i];
    return sum;
}
```

- `buf` 是**静态区**（读写数据段 `.data`）分配的数组，链接后空间就分配好了，`buf` 的地址是**链接时确定的常量**；
- dump 出来看：`08049908 <buf>`：`0A 00 00 00 14 00 00 00`，即 `buf[0]=10(0x0A)`、`buf[1]=20(0x14)`，小端存放；
- `buf = &buf[0] = 0x08049908`。

**指令实现**（设 `i` 在 `ECX`、`sum` 在 `EAX`）：

```asm
addl  buf(, %ecx, 4), %eax     # sum += buf[i]（绝对地址 + 比例变址）
# 等价写法：先把首址装入 EDX，再用
addl  0(%edx, %ecx, 4), %eax   # sum += buf[i]
addl  $1, %ecx                 # i++
```

**要点**：
- 静态数组的地址是**常数**，所以可以直接写 `buf(, %ecx, 4)`——这种寻址方式叫"**绝对寻址 + 比例变址**"（教材也写作"直接寻址 + 比例变址"）；
- 比例因子 `4` 说明**元素类型是 int（4 字节）**；`sum`、`i` 是 int，所以都用 `addl`；
- 编译器通常**先把首址放进寄存器（如 `EDX`）**，再用 `0(%edx,%ecx,4)` 这种"基址 + 比例变址"形式，这样可以省掉指令里的 32 位绝对地址、指令更短。

#### 4.4 单选题（P23）

> 假定全局 `double` 型数组 `a` 的起始地址为 `0x804908c`，则 `a[i]` 的地址是（ ）

| 选项 | 内容 | 判断 |
|---|---|---|
| A | `0x804908c+i` | ✘ 忘了乘元素大小 |
| B | `0x804908c+2×i` | ✘ 那是 `short` |
| C | `0x804908c+4×i` | ✘ 那是 `int`/指针 |
| D | `0x804908c+8×i` | ✔ `double` 占 8 字节 |

**答案：D**。

#### 4.5 课程回顾：可执行文件的存储器映像（P24）

理解"数组到底放在哪"必须回到进程的虚拟地址空间：

```text
0xC0000000 ┌───────────────┐ ← 内核虚存区（用户不可访问，1GB）
           │               │
           ├───────────────┤
           │ 用户栈 stack  │ ← 动态生成，向【低地址】增长
           │      ↓        │
           ├───────────────┤
           │ 共享库区域     │
           ├───────────────┤
           │ malloc 堆 heap│ ← 向【高地址】增长（brk）
           ├───────────────┤
           │ .data  .bss   │ ← 读写数据段（全局/静态变量）
           ├───────────────┤
           │ .init .text .rodata │ ← 只读代码段（常量、指令）
0x08048000 └───────────────┘
           │    未使用      │
0          └───────────────┘
```

ELF 目标文件的各个 section：

| 节 | 内容 |
|---|---|
| ELF 头 / 程序（段）头表 | 描述如何映射到虚存 |
| `.init` | 初始化代码 |
| `.text` | 机器指令 |
| `.rodata` | 只读数据（字符串常量、跳转表） |
| `.data` | 已初始化的全局/静态变量（如 `int buf[2]={10,20}`） |
| `.bss` | 未初始化（或初始化为 0）的全局/静态变量 |
| `.symtab` / `.debug` / `.line` / `.strtab` | 符号表、调试信息等（不装入内存） |

> **一句话**：全局/静态数组 → `.data`/`.bss`（静态数据区）；`auto` 数组 → **栈区**；`malloc` 出来的 → **堆**。

#### 4.6 栈区数组的存放和访问（P25）

```c
int adder()
{
    int buf[2] = {10, 20};
    int i, sum = 0;
    for (i = 0; i < 2; i++)
        sum += buf[i];
    return sum;
}
```

- `buf` 是 `auto` 型（默认存储类型），所以**分配在栈中**，其首址必须**通过 `EBP` 来定位**（因为地址在运行时才确定）；
- 栈帧里的位置：`buf[0]` 在 `EBP-8`、`buf[1]` 在 `EBP-4`：

```text
高地址
  EBP → ┌──────────────────┐
        │ EBP 在 P 中的旧值 │
  EBP-4 │ buf[1] = 20      │
  EBP-8 │ buf[0] = 10      │
  EBP-12│ ……               │
低地址  └──────────────────┘
```

**初始化指令**：

```asm
movl  $10, -8(%ebp)        # buf[0] 的地址 = R[ebp]-8，将 10 赋给 buf[0]
movl  $20, -4(%ebp)        # buf[1] 的地址 = R[ebp]-4，将 20 赋给 buf[1]
```

**取首址的指令**（"若 buf 首址要在 EDX 中"）：

```asm
leal  -8(%ebp), %edx       # EDX = &buf[0] = R[ebp]-8
```

**要点**：
- **"数组在栈上、下标越大地址越高"**：`buf[0]` 在最低地址 `EBP-8`，`buf[1]` 在 `EBP-4`，与内存中"正序排列"一致；
- 取地址用 **`leal`**（算地址，不访存），取元素值才用 `movl`；
- `EDX = &buf[0]`（基址），`ECX = i`（变址），之后 `sum += buf[i]` 就是 `addl (%edx,%ecx,4), %eax`；
- 与静态数组的区别：静态数组可用**绝对地址**直接寻址，`auto` 数组只能用 **`EBP` 相对**的基址寻址。

#### 4.7 单选题（P26）

> 假定局部 `int` 型数组 `a` 的首地址在 `EDX` 中，`i` 在 `ECX` 中，现要将 `a[i]` 取到 `EAX` 相应宽度的寄存器中，则所用的汇编指令是（ ）

| 选项 | 内容 | 判断 |
|---|---|---|
| A | `movw (%edx,%ecx,2),%ax` | ✘ `int` 是 32 位，不该用 `w`/`ax`，也不该用比例 2 |
| B | `movl (%edx,%ecx,2),%eax` | ✘ 比例因子错（那是 `short`） |
| C | `movw (%edx,%ecx,4),%ax` | ✘ 比例对了，但宽度用错 |
| D | `movl (%edx,%ecx,4),%eax` | ✔ `int`：32 位 + 比例因子 4 |

**答案：D**。

#### 4.8 数组与指针（P27）

- 前提：**指针变量的目标数据类型与数组类型相同**，指针才可以指向数组或数组中任意元素；
- 以下两段**功能完全相同**，都是让 `ptr` 指向 `a[0]`：

```c
/* (1) 定义时初始化 */        /* (2) 先定义后赋值 */
int  a[10];                  int  a[10], *ptr;
int *ptr = &a[0];            ptr = &a[0];
```

- `a` 的值就是其**首地址**，即 `a = &a[0]`，因而 `a = ptr`，从而：

```text
&a[i] = ptr+i = a+i
a[i]  = ptr[i] = *(ptr+i) = *(a+i)
```

**关键：`ptr+i` 不是地址加 `i` 个字节，而是加 `i` 个"元素"**：

```text
ptr + i  ⇔  0x8048A00 + 4*i        （int → 4 字节）
```

**小端存放的例子**（P27 图）：数组首址 `0x8048A00` 在 `ptr` 中。

```text
0x08048A00  ┌──────┐
            │ 01H  │
            │ 23H  │   a[0] = *ptr      = 0x67452301
            │ 45H  │
            │ 67H  │
0x08048A04  ├──────┤
            │ ABH  │
            │ CDH  │   a[1] = *(ptr+1)  = 0x00EFCDAB
            │ EFH  │
            │ 00H  │
            └──────┘
```

- 小端方式下，`01 23 45 67` 这 4 个字节按低地址存低字节，读成 `int` 就是 **`0x67452301`**；
- 第二组 `AB CD EF 00` → **`0x00EFCDAB`**；
- `ptr+i` = `0x8048A00 + 4*i`。

**两条易错区别**：

| 名称 | 性质 | 能否被赋值 |
|---|---|---|
| 数组名 `a` | **地址常量**（等价于 `&a[0]`） | 不能（`a = p` 是错误） |
| 指针变量 `ptr` | 变量，存放地址 | 能（`ptr = p`） |

#### 4.9 数组元素在内存中的访问（P28、P29）

设 `int A[N]` 的首址 `SA` 在 **`ECX`**，下标 `i` 在 **`EDX`**，结果放 **`EAX`**：

| 序号 | 表达式 | 类型 | 值的计算方式 | 汇编代码 | 是否访存 |
|---|---|---|---|---|---|
| 1 | `A` | `int *` | `SA` | `leal (%ecx), %eax` | 否 |
| 2 | `A[0]` | `int` | `M[SA]` | `movl (%ecx), %eax` | **是**（基址） |
| 3 | `A[i]` | `int` | `M[SA+4*i]` | `movl (%ecx,%edx,4), %eax` | **是**（基址+比例变址） |
| 4 | `&A[3]` | `int *` | `SA+12` | `leal 12(%ecx), %eax` | 否 |
| 5 | `&A[i]-A` | `int` | `(SA+4*i-SA)/4 = i` | `movl %edx, %eax` | 否 |
| 6 | `*(A+i)` | `int` | `M[SA+4*i]` | `movl (%ecx,%edx,4), %eax` | **是**（基址+比例变址） |
| 7 | `*(&A[0]+i-1)` | `int` | `M[SA+4*i-4]` | `movl -4(%ecx,%edx,4), %eax` | **是**（基址+比例变址+位移） |
| 8 | `A+i` | `int *` | `SA+4*i` | `leal (%ecx,%edx,4), %eax` | 否 |

**逐条理解**：
- 第 1、4、8 行的结果都是**地址（指针）**，所以用 **`leal`** 算地址、不访存；
- 第 2、3、6、7 行都要**取出元素值**，所以用 `movl`，都需要访存；
- 三种寻址方式正好全覆盖：**基址**、**基址+比例变址**、**基址+比例变址+位移**；
- 比例因子为 **4**，因为数组元素类型是 `int`；
- 第 5 行体现了"**指针相减得到的是元素个数，不是字节数**"——编译器直接在编译期把 `/4` 消化掉了，只剩一条 `movl %edx,%eax`；
- 第 7 行 `-4(%ecx,%edx,4)` 中的位移 `-4` 就来自 `-1` 个元素（`-1*4`）。

#### 4.10 单选题（P30）

> 某 C 程序中有 `int a[10]; int *ptr = &a[0];`，则 `ptr+i` 的值为（ ）

| 选项 | 内容 | 判断 |
|---|---|---|
| A | `a[0]` 地址 + `i` | ✘ 按字节加，错 |
| B | `a[0]` 地址 + `2×i` | ✘ 那是 `short` |
| C | `a[0]` 地址 + `4×i` | ✔ `int` → 每个元素 4 字节 |
| D | `a[0]` 地址 + `8×i` | ✘ 那是 `double` |

**答案：C**。

#### 4.11 指针数组和多维数组（P31）

- **指针数组**：由若干**指向同类目标的指针变量**组成的数组，一般定义形式：

```c
存储类型  数据类型  *指针数组名[元素个数];
```

- 例：`int *a[10];` 定义了一个指针数组 `a`，它有 10 个元素，**每个元素都是一个指向 `int` 的指针**（共 40 字节，每元素 4 字节）；
- **一个指针数组可以实现一个二维数组**：`a[i]` 存的是第 `i` 行的首地址，`a[i][j]` 就是 `*(*(a+i)+j)`。

```text
a ┌────────┐         ┌───┬───┬───┬───┐
  │ a[0] ──┼────────→│ 第0行 4 个 int  │
  │ a[1] ──┼────┐    └───┴───┴───┴───┘
  │  …     │    │    ┌───┬───┬───┬───┐
  │ a[9]   │    └───→│ 第1行 4 个 int  │
  └────────┘         └───┴───┴───┴───┘
    指针数组（40B）      各行可以任意位置、长度也可以不同
```

**对比易混点**：

| 声明 | 含义 | `sizeof` | 加 1 后的位移 |
|---|---|---|---|
| `int *a[10]` | **指针数组**：10 个 `int*` | 40 | 移到下一个指针（+4） |
| `int (*a)[10]` | **数组指针**：指向"含 10 个 int 的数组" | 4 | 跳过整行（+40） |

#### 4.12 程序分析：二维数组与指针数组（P32）

```c
main()
{
    static short num[ ][4] = { {2, 9, -1, 5},
                               {3, 8, 2, -6} };
    static short *pn[ ]    = { num[0], num[1] };
    static short s[2]      = { 0, 0 };
    int i, j;
    for (i = 0; i < 2; i++) {
        for (j = 0; j < 4; j++)
            s[i] += *pn[i]++;
        printf("sum of line %d：%d\n", i+1, s[i]);
    }
}
```

**内存 dump（`objdump -s` 结果）**：

```text
08049300 <num>:
08049300：  02 00 09 00 ff ff 05 00  03 00 08 00 02 00 fa ff
08049310 <pn>:
08049310：  00 93 04 08  08 93 04 08
08049318 <s>:
08049318：  00 00 00 00
```

**逐项解读**：

| 符号 | 值 / 位置 | 说明 |
|---|---|---|
| `num` | `0x8049300` | `short[2][4]`，**按行优先**存放，共 16 字节 |
| `num[0]` | `0x8049300` | 第 0 行：`02 00 09 00 ff ff 05 00` → 2, 9, −1(0xFFFF), 5 |
| `num[1]` | `0x8049308` | 第 1 行：`03 00 08 00 02 00 fa ff` → 3, 8, 2, −6(0xFFFA) |
| `pn` | `&pn[0] = 0x8049310` | `short *[2]`，每元素 4 字节 |
| `pn[0]` | `M[0x8049310] = 0x8049300` | 指第 0 行 |
| `pn[1]` | `M[0x8049314] = 0x8049308` | 指第 1 行 |
| `s` | `0x8049318` | `short[2]`，初值 `{0,0}` |

**`pn[i]` 的求值**：`pn[i] = *(pn+i) = M[pn + 4*i]`（指针元素 4 字节）。例如 `i=1` 时 `pn[1] = M[0x8049310+4] = M[0x8049314] = 0x8049308`。

**`s[i] += *pn[i]++;` 的指令序列**（设 `i` 在 `ECX`、`s[i]` 在 `AX`、`pn[i]` 在 `EDX`）：

```asm
movl  pn(, %ecx, 4), %edx     # EDX = pn[i]（取指针值）
addw  (%edx), %ax             # AX += *pn[i]（short → 用 addw）
addl  $2, pn(, %ecx, 4)       # pn[i] += 2：指针后移一个 short（2 字节）
```

**要点**：
- `*pn[i]++` 是"先取 `*pn[i]` 参加运算，再让 `pn[i]` 自增"——**自增的是指针本身**（`pn[i]` 这个指针元素），不是 `*pn[i]` 的值；
- `pn` 是**指针数组**，元素本身是指针（4 字节），所以取 `pn[i]` 用 `pn(,%ecx,4)`；
- `pn[i] += 2` 而不是 `+1`：因为 `pn[i]` 是 `short *`，加 1 个元素 = 加 2 个字节；
- 内层循环 4 次，`pn[i]` 依次指向该行的 4 个 `short`，所以 `s[i]` 最终是该行 4 个元素之和；
- `static short num[][4]` 省略第一维长度是合法的（编译器能由初值推出是 2 行），**但第二维不能省**——因为要靠它算行大小。

**预期输出**：

```text
sum of line 1：15          # 2+9-1+5 = 15
sum of line 2：7           # 3+8+2-6 = 7
```

#### 4.13 单选题（P33）

> 对数组变量 `b` 的声明为 `int b[10][5]`，有 `for(i=0;i<10;i++) for(j=0;j<5;j++) sum += b[i][j];`。设执行 `sum += b[i][j]` 时 `sum` 在 `EAX`、`b[i][0]` 所在地址在 `EDX`、`j` 在 `ESI`，则对应指令格式可以是（ ）

| 选项 | 内容 | 判断 |
|---|---|---|
| A | `addl 0(%edx, %esi, 4), %eax` | ✔ 基址 `b[i][0]` + 变址 `j` × 比例 4（`int`） |
| B | `addl 0(%esi, %edx, 4), %eax` | ✘ 基址/变址反了：`j*4 + b[i][0]` 的语义被颠倒 |
| C | `addl 0(%edx, %esi, 2), %eax` | ✘ 比例因子错（那是 `short`） |
| D | `addl 0(%esi, %edx, 2), %eax` | ✘ 基址/变址反了，且比例因子也错 |

**答案：A**。

> 这类题的固定套路：**"数组首址（行首地址）当基址，下标当变址，比例因子 = 元素大小"**。

#### 4.14 数组的分配和访问——小结（P34）

1. **全局和静态数组**的存放位置：**静态数据区**（`.data` / `.bss`）；
2. **`auto` 型数组**的存放位置：**栈区**；
3. 数组的主要寻址方式：**基址 + 比例变址 + 位移**（比例因子 = 元素大小）；
4. 指针变量可以指向数组中的**任意元素**；
5. **指针数组可以实现二维数组**。

### 5. 结构体的分配和访问（P35–P44）

#### 5.1 结构体的基本概念（P36）

| 概念 | 说明 |
|---|---|
| 结构体 | 可以把**不同类型**的数据结合在一个数据结构中 |
| 成员（字段） | 组成结构体的每个数据 |
| 成员引用 | `结构体变量名.成员名` 或 `结构体地址->成员名`（即 `(*p).成员名`） |

课件抛出两个问题（本节要回答的）：

1. 在**机器级层面**，结构体成员该如何访问？
2. 结构体变量作为函数参数时，该用**值**还是**地址**传参？

#### 5.2 结构体成员在内存中的存放和访问（P37）

```c
struct cont_info {
    char     id[8];
    char     name[12];
    unsigned post;
    char     address[100];
    char     phone[20];
};
struct cont_info x = {"0000000", "ZhangS", 210022,
                      "273 long street, High Building #3015", "12345678"};
```

**成员偏移量 = 前面所有成员大小之和**（本课例子中的类型都能自然对齐，暂不涉及填充）：

| 成员 | 大小(B) | 偏移量 | 若 `x` 在 `0x8049200` 时的首地址 |
|---|---|---|---|
| `id` | 8 | 0 | `0x8049200` |
| `name` | 12 | 8 | `0x8049208` |
| `post` | 4 | 20 | `0x8049214` |
| `address` | 100 | 24 | `0x8049218` |
| `phone` | 20 | 124 | `0x804927C` |
| **合计** | **144** | — | — |

```text
       ┌──────────────┐ ← 0x8049200  &x = &(x.id)
 0  id  │ "0000000"    │
  8  name│ "ZhangS"     │ 0x8049208
 20  post│ 210022       │ 0x8049214
 24  addr│ "273 long…"  │ 0x8049218
124  phone│ "12345678"  │ 0x804927C
144        └──────────────┘
```

**三条定位规则**：

1. 分配在**栈中**的 `auto` 结构型变量，首地址由 **`EBP`（或 `ESP`）** 定位；
2. 分配在**静态区**的结构型变量，首地址是一个**确定的静态区地址**；
3. 结构型变量 `x` 各成员的首址都可用"**基址 + 偏移量**"的寻址方式。

**访问成员的指令**（设 `&x` 在 `EDX` 中）：

```asm
movl  20(%edx), %eax        # eax = x.post  （取成员【值】：20 = 0x14 = x.post 的偏移）
```

**要点**：
- **取成员的值**用 `movl 偏移(%edx)`；**取成员的地址**要用 `leal 偏移(%edx)`（如 `leal 8(%edx),%eax` 得到 `&x.name`）；
- `post` 的偏移是 `8+12=20`（十进制），也就是 `0x14`；
- 字符串成员初始化后：`0x8049208`–`0x804920D` 是 `"ZhangS"`，`0x804920E` 是 `'\0'`，`0x804920F`–`0x8049213` 都是空字符（`0`）——**数组长度固定，没用满的部分补 0**；
- 结构体成员的偏移是**编译期常量**，所以一条 `mov` 就能访问到，不需要像数组那样动态算。

#### 5.3 单选题（P38）

> `struct cont_info { char id[8]; char name[16]; unsigned post; char address[125]; char phone[20]; };`
> 若变量 `x` 的数据类型为 `struct cont_info`，`x` 的首地址为 `0x8049820`，则字段 `x.phone` 的起始地址为（ ）

偏移累加：`8 + 16 + 4 + 125 = 153 = 0x99`，所以 `&x.phone = 0x8049820 + 0x99 = 0x80498B9`。

| 选项 | 地址 | 判断 |
|---|---|---|
| A | `0x80498b9` | ✔ `+0x99`，即 `phone` 的偏移 153 |
| B | `0x80498cd` | ✘ `+0xAD(=173)`，那是**加上 `phone` 自己 20 字节后**的"结构体尾"（无填充时） |
| C | `0x8049973` | ✘ 偏移算错 |
| D | `0x8049993` | ✘ 偏移算错 |

**答案：A**。

> 解题口诀：**从第一个成员开始，把前面每个成员的"长度"逐个累加，就得到当前成员的偏移量；数组要按"元素大小 × 元素个数"整体算**。

#### 5.4 结构体数据作为入口参数（P39）

```c
void stu_phone1(struct cont_info *s_info_ptr)   /* 按地址调用 */
{
    printf("%s phone number: %s", (*s_info_ptr).name, (*s_info_ptr).phone);
}

void stu_phone2(struct cont_info s_info)        /* 按值调用 */
{
    printf("%s phone number: %s", s_info.name, s_info.phone);
}
```

调用方式：

```c
stu_phone1(&x);     /* 只传一个指针（4 字节） */
stu_phone2(x);      /* 把整个结构体（144 字节）复制到参数区 */
```

| 维度 | 按值传递（`stu_phone2(x)`） | 按地址传递（`stu_phone1(&x)`） |
|---|---|---|
| 传什么 | 所有成员**逐个复制**到栈中参数区 | 只传**指向结构体的指针** |
| 时间开销 | 大（需要很多条 `mov`/`rep movs`） | 小（一条 `push`/`mov`） |
| 空间开销 | 大（参数区 = `sizeof(struct)`） | 小（4 字节） |
| 能否回写结果 | **不能**（改的是副本） | 能（通过指针改原变量） |

> 结论：**结构体变量应该按地址传参**（除非确实需要一份独立副本）。

#### 5.5 两种传参方式的栈帧对比（P40）

```text
【按地址调用 stu_phone1(&x)】                    【按值调用 stu_phone2(x)】
 调用者栈帧                                      调用者栈帧
 ┌────────────────────┐                          ┌────────────────────┐
 │ ……                 │                          │ "12345678"(phone)  │
 │ 0x8049200（指针）   │ ← 参数区只有 4 字节      │ ……                 │
 │ 返回地址            │                          │ 210022             │
 ├────────────────────┤                          │ "ZhangS"  ← EBP+16 │
 │ EBP 的旧值  ← EBP   │                          │ "0000000"          │
 │ （无局部变量）      │                          │ 返回地址           │
 └────────────────────┘                          ├────────────────────┤
                                                 │ EBP 的旧值  ← EBP  │
 静态区 x（0x8049200）:                           └────────────────────┘
   0x8049200 "0000000"
   0x8049208 "ZhangS"                            静态区 x 仍在原处不动
   0x8049214 210022
   0x8049218 "……"
   （phone）"12345678"
```

**对比要点**：
- 按地址：参数区只占 **4 字节**（一个指针），被调用者通过 `EBP+8` 拿到指针，再二重间接访问静态区的 `x`；
- 按值：参数区要复制**整个结构体**（144 字节），`EBP+8` 处就是 `x.id`，`EBP+8+8 = EBP+16` 处是 `"ZhangS"`（`name` 的偏移是 8）；
- 按值方式下，被调用者**改的是参数区副本**，调用者静态区的 `x` 不受影响——这就是 5.4 中"更新后的数据无法在调用过程使用"的机器级原因。

#### 5.6 按地址传参时结构体成员的访问（P41）

`(*s_info_ptr).name` 可以写成 `s_info_ptr->name`。执行以下两条指令后：

```asm
movl  8(%ebp), %edx         # EDX = s_info_ptr = 0x8049200（x 的首址）
leal  8(%edx), %eax         # EAX = 0x8049200 + 8 = 0x8049208 = &x.name
```

`EAX` 中存放的是字符串 `"ZhangS"` 在**静态存储区**内的首地址 `0x8049208`（后续 `printf` 用 `%s` 就打印这个地址开始的字符串）。

**要点**：
- `8(%ebp)` 是第一个参数（指针本身），`8(%edx)` 才是成员的偏移——**两层"8"含义完全不同**；
- 取成员地址用 `leal`（因为要传给 `%s`），不是 `movl`。

#### 5.7 按值传参时结构体成员的访问（P42）

```asm
leal  8(%ebp), %edx         # EDX = EBP+8 = 参数区中结构体副本的首址
leal  8(%edx), %eax         # EAX = EBP+16 = 副本中 name 的首址
```

`EAX` 中存放的是 `"ZhangS"` 在**栈内参数区**的首地址（`EBP+16`）。

**结论（P42 原文）**：
- `stu_phone1` 和 `stu_phone2` **功能相同**，但后者**开销大**：它需要对结构体成员整体从静态区**复制到栈中**，需要很多条 `mov` 或其他指令，执行时间更长，并占更多栈空间和代码空间；
- 特别是，**按值传递时无法获得更新后的结果**。

#### 5.8 单选题（P43）

> `struct cont_info { char id[8]; char name[16]; unsigned post; char address[100]; char phone[20]; };`
> 若变量 `x` 的类型为 `struct cont_info`，`x` 的首地址在 `EDX` 中，则 `unsigned xpost = x.post;` 对应的汇编指令为（ ）

`post` 的偏移 = `8 + 16 = 24 = 0x18`，且这是**取值**（不是取地址），所以用 `movl 0x18(%edx), %eax`。

| 选项 | 内容 | 判断 |
|---|---|---|
| A | `movl 0x24(%edx), %eax` | ✘ 偏移算成 36（多加了 `post` 自身 4 字节之类） |
| B | `movl 0x18(%edx), %eax` | ✔ 偏移 24，且用 `movl` 取值 |
| C | `leal 0x24(%edx), %eax` | ✘ 既偏移错、又是取地址（`leal`）而非取值 |
| D | `leal 0x18(%edx), %eax` | ✘ 偏移对，但 `leal` 取的是**地址**，不是值 |

**答案：B**。

> 两句口诀：**偏移 = 前面成员长度之和**；**取"值"用 `mov`，取"地址"用 `lea`**。

#### 5.9 结构体的分配和访问——小结（P44）

1. 结构体成员访问通常采用 **"基址 + 位移"** 的寻址方式（位移 = 成员偏移量）；
2. 结构体变量**应该按地址传参**（省时间、省空间、能回写）。

#### 6.2 高频考点与易错点

| 易错点 | 正确认识 |
|---|---|
| 逆向工程就是逐条指令"翻译"回 C | 一条 C 语句通常对应**多条**机器指令，要从序言/结束、`call`、`jcc`、寻址方式四类线索综合反推 |
| 参数地址是 `EBP+4` 起 | `EBP+0` 旧 EBP、`EBP+4` 返回地址、**`EBP+8` 起才是参数** |
| 参数从左往右入栈 | IA-32 **从右往左**，**最右边参数地址最大** |
| `$0x40` 与 `$40` 一样 | AT&T 里 `$0x40=64`、`$40=40`，`sub` 后 `ESP` 差 24 字节 |
| `4(%esp)` 与 `4(%ebp)` 是一回事 | 完全不同；`subl` 之后 `ESP` 与 `EBP` 相差整个帧大小 |
| `call` 不改变 `ESP` | `call` 会**压入返回地址**（`ESP-4`），返回后恢复 |
| 看到 `jg .L1` 就写成 `if (x > -100)` | `jg` 是"条件成立才跳"，而它跳到的是 **else 体**，所以 if 的条件要**取反**：`if (x <= -100)` |
| 循环终止条件都写成 `i<n` | 要看 `jne` 还是 `jl`：`jne` 对应 `i != n` |
| `lea` 和 `mov` 可互换 | `lea` **只算地址不访存**；取成员"值"必须用 `mov` |
| 所有数组元素大小都是 4 | 取决于元素类型：`char`=1、`short`=2、`int`/指针=4、`double`=8 |
| 指针数组元素大小等于所指类型大小 | `char *SA[10]`、`double *DA[10]` 的元素都是 **4 字节**（IA-32 指针） |
| `ptr+i` 等于地址 `+i` 字节 | 是加 **`i` 个元素**，即 `+sizeof(*ptr)*i`；编译器用比例因子实现 |
| 数组名可以赋值 | 数组名是**地址常量**，`a=p` 非法；`ptr=p` 合法 |
| 静态数组和 `auto` 数组寻址方式一样 | 静态数组可用**绝对地址**直接寻址；`auto` 数组必须经 **`EBP`** 相对寻址 |
| `int *a[10]` 与 `int (*a)[10]` 相同 | 前者是**指针数组**（10 个指针，40B），后者是**数组指针**（4B） |
| 二维数组 `b[i][j]` 用比例因子 2 | 比例因子 = **元素类型**大小，`int` → 4 |
| 指针相减得到字节差 | 指针相减得到**元素个数**（编译器在编译期已把 `/sizeof` 消化掉） |
| 结构体成员偏移要看对齐 | 本课例子都自然对齐；**数据对齐留待 3.7（下）**，但对 `char` 数组 + `unsigned` 这类组合本课按"直接累加"算即可 |
| 结构体按值传参也能回写结果 | 改的是**参数区副本**，调用者的变量不变；要回写必须按地址传 |
| 结构体按值传参开销很小 | 要复制**整个结构体**，时间和空间开销都大，还可能多占代码空间 |
