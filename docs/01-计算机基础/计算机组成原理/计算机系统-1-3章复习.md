### 期末重点（浮点数的表示）

- **规格化数**：阶码 E 既非全 0 也非全 1，尾数隐含最高位 1
- **非规格化数**：E 全 0，尾数不含隐含的 1，用于表示 0 与接近 0 的数
- **E 全 1 是特殊值**，不表示普通数值：
  - M 全为 0 → 按符号位 S 得到 `+∞` / `-∞`
  - M 非全 0 → `NaN`（非数值）
- 因此**最大规格化正数**的阶码是 `FEH`(254)，阶码全 1 已留给无穷与 NaN

> **注意** · 已修正（2026-11-06）· 待复核
> 原笔记写「最大的正数和最小的负数 E 为全 1」，与 IEEE 754 冲突，已按标准改正；请以课堂课件为准复核。

#### fp32(1S 8E 23M)

移码为127（7FH）

V = (-1)^s * 1.M * 2^(E - 7FH)   ( 1<=E <= FEH（254）)

V = (-1)^s * 0.M * 2^( -126 )    (E 为00H)

#### fp16(1S 5E 10M)

移码为15（0FH）

V = (-1)^s * 1.M * 2^(E - 0FH)   ( 1 <= E <= 1EH，即 1–30)

V = (-1)^s * 0.M * 2^( -14 )    (E 为00H)

#### 总结

阶码偏移量（bias）：8 位为 7FH(127)、5 位为 0FH(15)、11 位为 3FFH(1023)

##### 小字长转大字长

- 原数据位无符号类型，进行0拓展
```c
unsigned char uc = 254;      /* 位模式 1111 1110 */
short s;                    
s = (short)uc;                          /* 零扩展 → 0000 0000 1111 1110 */
/* s = 254（按补码解释） */
```

- 原数据为有符号类型，进行符号拓展

```c
char c = -128;      /* 位模式 1000 0000 */
short s;                    
s = (short)c;                          /* 符号扩展 → 1111 1111 1000 0000 */
/* s = -128（按补码解释） */
```

## 第三章（程序的转化和机器级表示）

### 概述

- 简化对指令行为的说明，采用寄存器传送语言（RTL）
- **微指令**：硬件内部最底层的控制信号，程序员不可见
- **伪指令**：汇编器的指示（如 `.section`、`.globl`），不生成机器指令
- **机器指令**：CPU 可执行的二进制编码
- **汇编指令**：机器指令的助记符形式，与机器指令基本一一对应

> **提示** · 概念已更正 · 待复核
> 原笔记把「伪指令」记为软件指令、把「机器指令」记为「两者之间」，与通行定义不符，已按 CSAPP / 课件通行说法改写。

编译流程：`高级语言 --(编译器 compiler)--> 汇编语言 --(汇编器 assembler)--> 可重定位目标文件 --(链接器 linker)--> 可执行文件`

![image-28](../../../assets/images/计算机系统基础/image-28.png)

一个高级语言程序可对应多个机器级程序（编译优化）

### ISA(指令集体系结构)

可执行的指令的集合，包括指令格式、操作种类以及每种操作对应的操作数的相应规定；

- 指令可以接受的操作数的类型；
- 操作数所能存放的寄存器组的结构，包括每个寄存器的名称、编号、长度和用途；
- 操作数所能存放的存储空间的大小和编址方式；
- 操作数在存储空间存放时按照大端还是小端方式存放；
- 指令获取操作数的方式，即寻址方式；
- 指令执行过程的控制方式，包括程序计数器、条件码定义等

### 目标文件

![image-32](../../../assets/images/计算机系统基础/image-32.png)

二、 可重定向文件（Relocatable Object File）

常见后缀：Linux下是 .o，Windows下是 .obj。
生成者：汇编器（Assembler）。
核心特点：
地址未确定（从0开始）：它内部的代码和数据都假定自己是从地址 0 开始的。
包含符号表和重定位表：里面记录了“我这里有段代码引用了外部函数   printf，但我不知道它在哪，请链接器告诉我”。
不能直接运行：因为它还有“断头路”（未解析的外部符号），操作系统无法直接加载它执行。
作用：作为链接器（Linker）的输入。
三、 可执行文件（Executable File）
常见后缀：Linux下通常是 a.out 或没有后缀，Windows下是 .exe。
生成者：链接器（Linker）。
核心特点：
地址已确定：链接器把所有的 .o 文件和库文件拼装在一起，解决了所有的“断头路”（符号解析），并且根据操作系统的内存布局，给代码和数据分配了具体的虚拟内存地址（重定位）。
包含程序入口点：比如在ELF格式中，有明确的 Entry point 地址，告诉CPU第一条指令从哪里开始执行。
可以直接运行：操作系统（Loader）可以直接把它加载到内存中，跳转到入口点开始执行。
作用：作为操作系统加载器的输入。

![image-37](../../../assets/images/计算机系统基础/image-37.png)

相对寻址（LA = (PC) + A）

结合图中的公式 LA = (SR) + (B) + (I)×S + A，假设我们在 C 语言中要访问一个二维数组或者结构体数组：

场景：访问 Arr[i].age（假设 Arr 是一个结构体数组）

(SR)：段寄存器，确定整个程序数据段在哪。

(B)：基址寄存器，指向数组 Arr 的第一个元素的首地址（起点）。

(I)：变址寄存器，存放循环变量 i（比如第 3 个元素）。

S：比例系数，结构体 Arr 的大小（比如每个结构体占 8 字节，S=8）。

A：位移量，指令中给定的固定偏移（比如 age 在结构体内部偏移 4 字节）

先将1个字或双字从SP或ESP指示的栈单元送到指定寄存器，然后执行R[sp]←R[sp]+2或R[sp]←R[sp]+4

popl表示双字出栈，popw表示字出栈

### 越界访问&缓冲区溢出

```c
test.c
#include<stdio.h>
#include<string.h>

void hacker(void)
{
	printf(“being hacked by 学号\n” );//注意这里的学号要改成自己的真实学号
}

void outputs(char *str)
{
	char buffer[16];
	strcpy(buffer, str);
	printf(“%s\n”,buffer);
}

int main(int argc, char *argv[])
{
	outputs(argv[1]);
	return 0;
}缓冲区溢出
```
越界访问/溢出可以发生在不同存储区，危害和利用方式不同：

- **栈溢出**：局部数组越界写，可覆盖返回地址、保存的寄存器 → 劫持控制流（test.c 就是这种）。
    
- **堆溢出**：`malloc` 得到的块越界写，可破坏堆元数据、相邻对象 → 任意写、控制流劫持。
    
- **全局/静态区溢出**：覆盖相邻全局变量、函数指针。
    
- **越界读**：可读出栈上残留的指针/canary、堆上的密钥等（Heartbleed 就是典型）。
#### 避免
栈地址随机化

栈破坏检查：
在函数准备阶段，在栈桢中的缓冲区底部与保存者寄存器之间加入随机特定值，恢复阶段检测特定值是否被更改，若更改则发生越界

可执行代码区域进行限制：
将程序栈区和堆区设置不可执行，让攻击者不能
