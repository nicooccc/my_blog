第一部分

程序执行概述（课件 1–18 页）

关键词：程序 = 指令序列；CPU = 周而复始取指执行；PC 控制执行流；周期分层；异常与中断打断正常流。

1. 程序与指令的关系（第 4 页）

  • 程序由一条条指令组成，指令按顺序存放在连续的存储单元中。
  • 程序的执行就是周而复始地执行一条条指令。正常情况下按存放顺序执行；遇到转移类指令（无条件转移、条件转移、调用、返回）时改变执行流。
  • 程序计数器 PC 保存“将要执行的指令”的地址，改变 PC 就等于改变执行顺序：
顺序执行→PC = PC + “1” 或 转移/调用→直接给 PC 赋值
引号的“1”是关键 PC + “1” 中的 “1” 不是数字 1，而是一条指令的长度：MIPS 等定长 32 位指令是 PC+4；x86 变长指令则是 PC+“当前指令字节数”。这是第 18 页投票题的考点。

2. CPU 的三种周期（第 5 页）

周期定义层级关系
指令周期取出并执行一条指令的时间；不同指令的指令周期可能不同最大
机器周期（CPU 周期 / 取指周期）完成一个基本操作（如取出一条指令）所需时间中
时钟周期（振荡周期）时钟频率的倒数，计算机中最基本、最小的时间单位；一个时钟周期只完成一个最基本动作最小
时钟周期 ≤ 机器周期 ≤ 指令周期
现代计算机的例外（第 69 页） 早期计算机有明确的“机器周期”；现代计算机已基本没有机器周期的概念，一个指令周期直接由若干个时钟周期（节拍）组成。这也是第 17 页题的背景。

3. 一条指令的执行过程（第 7、8 页）

CPU 运行程序 = 执行一条条指令。每条指令的功能都由以下基本操作组合实现：

  1. 取指：从 PC 所指内存取出指令送 IR，取“最长指令字节数”。
  2. 译码：根据不同指令译出不同控制信号。
  3. 取操作数：根据寻址方式确定源/目的操作数地址，访存或读寄存器。
  4. 执行：由 ALU 或加法器完成运算，计算目的地址。
  5. 回写：把结果写回寄存器或主存。
  6. 修改 PC：顺序则 PC + 当前指令长度，转移则把目的地址写入 PC。

此外还要在指令执行中查询异常、在指令结束时查询中断请求（第 8 页）。

4. 机器指令执行举例：add 函数与整数溢出（第 9–13 页）

课件给出 objdump -d test 反汇编的 add 函数，问：若 i=2147483647，j=2，结果是什么？

080483d4 <add>:  push %ebp → mov %esp,%ebp → sub $0x10,%esp
mov 0xc(%ebp),%eax   # eax = j = 2
mov 0x8(%ebp),%edx    # edx = i = 0x7fffffff
lea (%edx,%eax,1),%eax   # eax = edx + eax×1

lea (%edx,%eax,1), %eax 功能为 R[eax] ← R[edx] + R[eax]×1。代入数值（课件第 13 页图中 ALU 输入正是 7fffffff 与 2）：

0x7fffffff + 0x2 = 0x80000001
结果：有符号溢出 2147483647 是 32 位有符号整数最大值（0x7FFFFFFF）。加 2 后超出范围，按补码回绕成 0x80000001，即 −2147483647。这就是课件让算 this 例子的目的——演示 ALU 运算中溢出的硬件表现，也呼应第 14 页“ALU 运算结果发生溢出”属于异常。

课件第 10–11 页还逐步画出 push %ebp 的取指/译码/执行三阶段，展示了 PC→MAR→读内存→MDR→IR、ESP 减 4、写回等信号与寄存器变化，是理解“数据通路”的预备动画。

5. 打断程序正常执行的事件（第 14、15 页）

正常执行时，CPU 上电后只重复一件事：读出 PC 所指指令并执行。以下事件会打断它：

类别来源典型例子
内部异常CPU 内部非法操作码、段错误/缺页、ALU 溢出、除数为 0、断点、单步跟踪；硬故障中断（硬件线路异常）
外部中断（I/O 中断）CPU 外部 I/O 子系统采样计时到、网络包到达、磁盘读写完成
  • CPU 必须具备打断时的处理机制，称为异常控制 / 中断机制，相应处理逻辑叫中断机构。
  • 外部中断的处理：每条指令执行完 CPU 主动查询中断请求 → 有则把下条指令作为断点保存 → 转去执行“中断服务程序” → 结束后返回断点继续。这类事件与当前指令无关。

6. 本部分小结 · 投票题解析

小结（第 16 页）各种周期的概念 · 程序及指令的执行过程 · 机器指令执行举例 · 打断程序正常运行的事件。
【第 17 页】CPU 取出一条指令并执行所用的时间被称为（  ）
A. 时钟周期　　B. CPU 周期　　C. 机器周期　　D. 指令周期
答案 D
“取出并执行一条指令所用的时间”正是指令周期的定义。一个指令周期可分为取指、读操作数、执行并写结果等多个机器周期，而每个机器周期又由若干时钟周期组成。CPU 周期一般就等于机器周期。
【第 18 页】下列有关程序计数器 PC 的叙述中，错误的是（  ）
A. 每条指令执行后，PC 的值都会被改变
B. 每条指令顺序执行时，PC 的值总是自动加 1
C. 调用指令执行后，PC 的值一定是被调用过程的入口地址
D. 无条件转移指令执行后，PC 的值一定是被调用过程的入口地址
答案 D
课件解析区专门解释了 B：“顺序执行时 PC 总是自动加当前指令的长度，通常所说 PC+‘1’ 的 1 加了引号，指的就是一条指令长度”——所以 B 被认为是正确表述。而 D 混淆了转移与调用：无条件转移（jmp）执行后 PC 是转移的目标地址，不一定是“被调用过程的入口地址”；后者是调用指令（call）的结果（对应 C，正确）。故错误的是 D。
第二部分

数据通路（课件 19–36 页）

关键词：指令的执行部件；由组合逻辑 + 时序逻辑经总线/分散方式连接；“何时写入”由时序控制决定；时钟周期由最慢路径决定。

1. 从冯·诺依曼结构说起（第 20 页）

五大部件：输入设备、输出设备、存储器、运算器、控制器。早期部件间用分散方式相连；现在大多用总线方式；趋势是点对点高速连接。

辨析系统总线按传输内容分三类：数据线、地址线、控制线。控制器与存储器/运算器之间交换“控制信号与状态”。

2. 什么是数据通路 / 控制器（第 21 页）

概念定义角色
数据通路 DataPath指令执行过程中数据经过的路径，包含路径上的 ALU、通用寄存器、状态寄存器、cache、MMU、FPU、异常和中断处理逻辑等指令的执行部件
控制器 Control对指令译码，生成对应的控制信号，控制数据通路的动作指令的控制部件

记忆模型：CPU = DataPath（干活）+ Control（指挥），再与 Memory、Input、Output 交互。

3. 两类逻辑元件（第 22–24 页）

类型典型元件核心特点
组合逻辑元件（操作元件）加法器 Adder、译码器 Decoder、多路选择器 MUX、ALU输出只取决于当前输入；不受时钟控制；输入一样输出一样；经门延迟后改变并保持
时序逻辑元件（状态/存储元件）D 触发器、寄存器、存储器有存储功能；输入状态在时钟控制下被写入并保持到下一时钟；输出随时可读

元件间连接方式：总线连接 / 分散（专用线）连接。数据通路 = 操作元件 + 存储元件经总线或分散方式连接，完成数据的存储、处理与传送。

定时方式状态元件的值在时钟边沿改变：上升沿触发、下降沿触发、双边沿触发。边沿触发是现代寄存器最常用方式。

4. 时序控制与 D 触发器（第 25、26 页）

三个关键时间参数：

参数含义
建立时间 Setup Time触发时钟边沿之前，输入必须稳定的时间
保持时间 Hold Time触发时钟边沿之后，输入必须稳定的时间
锁存延迟 Clock-to-Q从触发边沿开始到输出 Q 状态改变的时间
Cycle Time = Clk-to-Q + 最长组合逻辑延迟（Longest Delay） + 建立时间 + 时钟偏移

理解：数据在时钟边沿被“发射”出来（Clk-to-Q），经过最长的一条组合逻辑路径（Longest Delay），必须在下一个时钟边沿的“建立时间”之前稳定下来，再考虑时钟到达不同寄存器的偏差（时钟偏移）。这条最长路径决定了整个 CPU 能跑多快——这也是流水线要切分组合逻辑的根本原因。

核心论断（第 26 页）只有状态元件能存储信息；操作元件必须从状态元件取输入、把输出写回状态元件。其输入是前一时钟生成的数据，输出是当前时钟所用的数据。

5. 总线式数据通路（第 27–32 页）

① 早期累加型（第 27 页）

最简单、分散连接，原型是 IAS 计算机。取指路径：PC→MAR, Read M, M→MBR→IBR→IR。

② 单总线数据通路（第 28–31 页）

四种基本操作的时序控制信号（标记为 L2，即在第 2 级/一个总线周期完成一步）：

基本操作控制信号序列周期数
寄存器间传送R0out, Yin1 Cycle
算术逻辑运算R1out, Yin → R2out, Add, Zin → Zout, R3in3 Cycles
从主存取字R1out, MARin → Read, WMFC → MDRout, R2in>3 Cycles
写字到主存R1out, MARin → R2out, MDRin → Write, WMFC>3 Cycles
WMFC = Wait for Memory Function Complete早期访存用异步方式，靠 MFC 应答信号；现代用同步方式，无需应答。单总线一个时钟只能传一个数据，效率很低。

③ 三总线数据通路（第 32 页）

  • 总线 A、B 分别传两个源操作数，总线 C 传结果；三条总线各传不同数据不冲突，因此不再需要暂存器 Y 和 Z。
  • 采用双口通用寄存器组，实现 R[R3] ← R[R1] op R[R2] 只需一个控制信号序列 R1outA, R2outB, op, R3inC，一个时钟周期即可完成。

6. 本部分小结 · 投票题解析

【第 34 页】下列有关数据通路的叙述，错误的是（  ）
A. 数据通路由若干操作元件和状态元件连接而成
B. 数据通路的功能由控制部件送出的控制信号决定
C. ALU 是数据操作元件，用于执行各类算术和逻辑运算
D. 通用寄存器属于状态元件，但不包含在数据通路中
答案 D
课件解析区明确：“数据通路由操作元件和状态元件连接而成，通用寄存器属于状态元件，包含在数据通路中。”数据通路的定义（第 21 页）就包含通用寄存器。故 D 错误。A、B、C 均正确。
【第 35 页】通常情况下，下列（  ）部件不包含在中央处理器（CPU）芯片中。
A. ALU　　B. 控制器　　C. 通用寄存器　　D. DRAM
答案 D
ALU、控制器、通用寄存器都在 CPU 芯片内；DRAM（动态随机存取存储器）属于主存，通常不在 CPU 芯片中（CPU 内的是 cache，一般由 SRAM 构成）。故选 D。
第三部分

指令流水线（课件 37–56 页）

关键词：让多条指令重叠执行以提高吞吐率；时钟周期由最长流水段决定；段数越多吞吐率越高但单条指令延时也变长；三类冒险会打断流水。

1. 洗衣例子：流水线的直觉（第 39–41 页）

4 人各洗一批衣服，每批要经过洗 30 min → 烘 40 min → 叠 20 min 三步。

方式总时间（N 批）4 批时
串行N × (30+40+20) = 90N 分钟360 min = 6 小时
流水线（尽快开始）30 + N×40 + 20 分钟30 + 160 + 20 = 210 min = 3.5 小时
结论流水线方式所用时间主要与最长阶段的时间有关（此处烘干 40 min）。假定每步时间均衡，比串行提高约 3 倍。这就是“Pipelining: It's Natural!”。

2. 五段流水线 IF–WB（第 42 页）

IF 取指令
按 PC 从存储器取指令→ ID 指令译码
产生控制信号→ OF 取操作数
读存储器/寄存器操作数→ EX 执行
对操作数完成指定操作→ WB 写回
结果写存储器/寄存器

3. 单周期 vs 流水线（第 43、44 页）

设最复杂指令的五步耗时：取指 200ps、译码+读操作数 50ps、ALU 100ps、读存储器 200ps、写寄存器 50ps。

指标单周期数据通路流水线数据通路
时钟周期200+50+100+200+50 = 600 ps（由最复杂指令决定）最长段 200ps + 段寄存器 50ps = 250 ps
CPI1理想情况下 ≈ 1（稳态每周期流出一条）
一条指令执行时间（延时）600 ps250×5 = 1.25 ns（反而更长）
吞吐率1/600ps ≈ 1.67 GIPS1/250ps = 4 GIPS
流水线的重要权衡（易考） 流水线提高了吞吐率（单位时间完成的指令数变多），但单条指令的延时可能变长（因为加入了段寄存器开销，且要等满 5 段）。程序总执行时间 = 指令条数 ÷ 吞吐率，所以整体更快。

4. 练习：插入流水段寄存器（第 45–49 页）

题干：6 个功能段 A~F 的组合逻辑延迟依次为 80 / 30 / 60 / 50 / 60 / 20 ps，最后一段需写寄存器，流水段寄存器延时 20 ps。求不同切分下的时钟周期、吞吐率、每条指令执行时间，以及寄存器插在哪里。

方案寄存器插入位置各段组合逻辑延迟(ps)时钟周期吞吐率指令执行时间
(1) 2 级C 与 D 之间（平衡点）80+30+60=170；50+60+20=130170+20=190ps1/190≈5.26 G2×190=380ps
(2) 3 级B–C、D–E 之间110；110；80110+20=130ps1/130≈7.69 G3×130=390ps
(3) 4 级A–B、C–D、D–E 之间80；90(30+60)；50；80(60+20)90+20=110ps1/110≈9.09 G4×110=440ps
(4) 5 级（吞吐率最大）A–B、B–C、C–D、D–E 之间80；30；60；50；80(60+20)80+20=100ps1/100=10 G5×100=500ps
规律总结（第 49 页汇总） 流水段越多 → 每段越短 → 时钟周期越短 → 吞吐率越高（5.26 → 7.69 → 9.09 → 10 G）；但单条指令执行时间反而变长（380 → 390 → 440 → 500 ps），因为段寄存器开销在累积。这是设计流水线时的基本矛盾。
做题方法① 先决定切几段、在哪切；② 把每段内的组合逻辑延迟相加，取最大值作为最长段；③ 时钟周期 = 最长段 + 寄存器延时；④ 吞吐率 = 1/时钟周期；⑤ 指令执行时间 = 段数 × 时钟周期。想吞吐率最大，就尽量让每段延迟接近最长段（80ps）。

5. 讨论题（第 50 页）

条件：五级流水 —— 取指 200ps、译码+读操作数 50ps、ALU 150ps、读存储器 200ps、写寄存器 50ps，段寄存器延时 50ps。

基准：最长段 200ps，时钟周期 = 200+50 = 250ps；吞吐率 4 GIPS；指令延时 5×250 = 1250ps。

  1. 段寄存器（额外开销）的影响：若忽略寄存器延时，时钟周期 200ps、吞吐率 5G、延时 1000ps；计入 50ps 后，周期升到 250ps（+25%），吞吐率降到 4G（−20%），延时升到 1250ps（+25%）。段寄存器开销会降低性能。
  2. 取指时间缩短 20%：200→160ps，最长段仍是“读存储器 200ps”。时钟周期不变（250ps），吞吐率与执行时间都不变——因为取指不是瓶颈段。
  3. ALU 时间延长：
    · 延长 20%：150→180ps，仍小于 200ps，最长段不变 → 周期 250ps、吞吐率 4G、延时 1250ps，均不变。
    · 延长 40%：150→210ps，超过 200ps 成为新瓶颈 → 周期 = 210+50 = 260ps，吞吐率 1/260≈3.85 GIPS，延时 5×260=1300ps。
    要点：只有改变最长段（瓶颈）才会影响时钟周期和吞吐率；非瓶颈段的小幅变化被“淹没”。

6. 流水线的冲突 / 冒险 Hazard（第 51 页）

Hazard：流水线遇到无法正确执行后续指令，或执行了不该执行的指令。课件注明“本部分只需大概了解”。

类型现象解决办法
结构冒险
硬件资源冲突		同一部件同时被不同指令使用增加部件：如指令存储器 IM 与数据存储器 DM 分开
数据冒险
数据相关		后面指令要用的结果，前面指令还没产生转发/旁路 Forwarding/Bypassing、前半周期读后半周期写；Load-use 冒险不能靠转发，需阻塞(stall)一周期；编译优化指令顺序
控制冒险
改变控制流		转移或异常改变流程，后继指令在目标地址产生前已被取出静态/动态分支预测；编译优化（分支延迟）

7. GPU 与 ARMv8 流水线（第 52、53 页）

  • GPU 流水线：专注大规模并行（图形渲染）。顶点处理 → 几何处理（可选）→ 光栅化 → 像素处理。每个顶点/像素可独立处理，高度并行。
  • ARMv8：Cortex-A53 有序八级流水，A57 乱序 15+ 级。关键技术：超标量（一周期发射多条）、分支预测、投机执行、高级乱序执行——都是为减少流水线停顿、提高吞吐率。

8. 本部分小结 · 投票题解析

小结（第 54 页）流水线时钟周期由最长流水段决定 · 流水线的吞吐率 · 流水线指令的执行时间。
【第 55 页】某计算机指令流水线由 4 个功能段组成，各段流经时间为 90ns、80ns、70ns、60ns（忽略段寄存器缓存时间），则 CPU 时钟周期至少是（  ）
A. 90ns　　B. 80ns　　C. 70ns　　D. 60ns
答案 A
流水线时钟周期由最长的流水段决定，与段寄存器缓存时间无关（题目已说明忽略）。最长段为 90ns，故时钟周期至少 90ns。
【第 56 页】6 个子功能 A~F 分别耗时 80/40/50/70/20/30 ps，段寄存器延时 20ps。把 E、F 合并构成 5 段流水线，其时钟周期至少是（  ）
A. 70ps　　B. 80ps　　C. 90ps　　D. 100ps (课件选项单位误写为 ns)
答案 D
合并 E、F 后各段为：A=80、B=40、C=50、D=70、EF=20+30=50 ps。最长段是 A 段 80ps。时钟周期 = 最长段 + 段寄存器延时 = 80+20 = 100ps，选 D。
第四部分

指令系统（课件 57–68 页）

关键词：规整、简单、一致的指令集有利于流水线；CISC 复杂庞大，RISC 精简规整；RISC-V 开源模块化。

1. 流水线友好的指令集特征（第 58 页）

  • 指令长度尽量一致——简化取指与译码。MIPS 定长 32 位，下址计算方便（PC+4）；x86 长度 1~17 字节不等，取指部件极其复杂。
  • 格式少、源寄存器位置相同——指令未知时就能取操作数。MIPS 的 rs、rt 位置固定，译码时即可读出；若位置随指令变化，须先判明类型才能取寄存器编号。
  • 只有 load/store 指令访存——减少操作步骤、规整流水线。MIPS 的 lw/sw 地址计算与运算指令步骤规整在同一周期；x86 运算类指令操作数可为内存数据，需额外算地址、访存、执行。
  • 内存中对齐存放——减少访存次数，利于流水线规整。
一句话规整、简单、一致（规整性）等特性有利于指令的流水线执行。

MIPS R 型指令格式（第 58 页）：op(6) | rs(5) | rt(5) | rd(5) | shamt(5) | func(6)，共 32 位。

2. CISC 与 RISC（第 59–62 页）

对比项CISC（复杂指令集）RISC（精简指令集）
指令系统指令多、寻址方式多、格式多、变长操作码/指令字指令少、寻址方式少、格式少、指令长度一致
访存方式各种指令都能访存（含运算指令），指令周期差距大RR 方式：除 Load/Store 外都只访问寄存器
指令周期长，多数指令需多个时钟周期短，流水线工作，简单指令一个周期甚至不到
控制器指令太复杂无法硬连线，只能用慢速微程序控制器硬连线控制器，不用或少用微程序
其他难编译优化；研制周期长、难调试维护（如 VAX-11/780：16 种寻址、303 条指令）大量通用寄存器减少访存；优化编译系统支持高级语言
著名的 20%–80% 规律（第 60 页） 对 CISC 测试发现：程序中最常使用的简单指令占 80%，但只占指令系统的 20%；而占指令总数 20% 的复杂指令却占用了控制存储器容量的 80%。这正是 RISC 的思想来源。1975 年 IBM 的 John Cocke 提出 RISC；1982 年第一代 RISC 机问世（伯克利 RISC-I、斯坦福 MIPS、IBM 801）。

80x86 Top 10 指令（第 61 页）：MOV M→R、Jcc、CMP、MOV R→M 等——简单指令占主要部分、使用频率高。

现状：MIPS 是典型 RISC，1982 年以来新指令集大多采用 RISC 体系结构；x86 因兼容需要保留 CISC 风格，但内部也借鉴了 RISC 思想。

3. RISC-V 与国产处理器（第 63–65 页）

  • RISC-V：第五代精简指令集，2010 年起源于加州伯克利；开源、免版税；采用模块化指令子集和可配置寄存器；有高性能与低功耗多版本；支持 32 位和 64 位。
  • 国产 RISC-V：2019.7 阿里平头哥发布玄铁 910；2019.8 兆易创新发布全球首个基于 RISC-V 内核的 32 位通用 MCU；腾讯、字节、百度、海思、紫光、华米、中兴等均参与。
  • LoongArch 龙架构：国产自主指令系统（课件第 65 页）。

4. 本部分小结 · 投票题解析

【第 67 页】下列有关 RISC 特征的描述中，错误的是（  ）
A. 指令格式规整，寻址方式少
B. 采用硬连线控制和指令流水线
C. 配置的通用寄存器数目不多
D. 运算类指令的操作数不访存
答案 C
RISC 特点之一是采用大量通用寄存器，以减少访存次数（第 62 页）。所以“配置的通用寄存器数目不多”错误。A（规整、寻址少）、B（硬连线+流水线）、D（RR 方式、运算不访存）都是 RISC 的正确特征。
本章小结（第 69、70 页） CPU 的基本功能是周而复始执行指令并处理异常/中断；CPU 最基本的部分是数据通路 + 控制单元。指令执行主要包括取指、译码、取数、运算、存结果。现代计算机一个指令周期直接由时钟周期组成；数据通路早期用总线方式（单/二/三总线），现代采用流水线方式；流水线冒险分结构、数据、控制三类。
